# BUG-027 / YKT-024

修正前dcd82e7、起票58a03c6。OperationFingerprint.canonicalBytesとResponseSnapshotCodec.compress/decompressの3箇所は、ByteArrayOutputStream.toByteArrayの返却配列だけをcallerで消去し、stream内部配列・成長前旧配列は消去していなかった。CanonicalFieldも保有copyの終了消去APIがなかった。静的な配列所有権追跡で確認し、実秘密値/heap dumpは採取していない。

修正: bounded WipingByteArrayOutputStreamを3箇所へ適用し、拡張時旧配列・reset/close時全容量をzero。書込み途中失敗でもfinallyでfield/text copyをzero。CanonicalRequest/Fieldのcloseで保有copyをzeroにし、caller入力配列を破壊しない。close後のrequest再利用は禁止。HMAC/golden/envelope/Deflater形式は変更しない。

| 横展開対象 | 結果・根拠 |
|---|---|
| HMAC canonical stream/input field | stream拡張/close、text/valueの例外finally、owner終了closeをPT-IDEM-WIPE-001～003で直接検査。既存OpenSSL vectorも再試験 |
| Inbox compress/decompress | 同streamへ置換、既存0/1/1,000,000byte・bomb/trailing/dictionary/fault・固定JCA/AAD/暗号・Login再送を非回帰 |
| AuthContextIdentity | AADの目的/table/session UUID/user/key metadataだけ。raw/password/業務bodyを保持せず当該secret buffer対象外 |
| Web AES codec | 直接配列/ByteBufferでtoByteArray複製なし、既存finally消去・改ざん/並行PTを非回帰 |
| 新Login caller | 匿名HMACを使用するcallerのtry-with-resourcesと全終了の消去確認は接続PTへ引継ぎ。未実装につき本sliceの完了へ数えない |

Javaの明示配列消去はJIT/GC/OSが作るすべてのcopyの完全消去保証ではない。管理可能な配列を消去する契約の試験であり、その制限を隠さない。正式run/commit/counter/hashは確定後追記。
