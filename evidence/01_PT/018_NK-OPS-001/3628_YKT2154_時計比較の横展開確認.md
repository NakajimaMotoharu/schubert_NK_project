# YKT2154：signed原点とLinux絶対期限を分離する

BUG2409の同原因は、任意signed原点のnanoTimeへ期間を加えた値をabsolute符号比較すること。Production source54d5、WebRuntimeStopのみ是正。検索結果はPG22026/clock-comparison-search.jsonに元12行/7pathを保存する。追加の直接nanoTime/nowNanos/getAsLong利用27行も元sourceから点検した。検索だけを完了根拠にせず、下記のdomain/演算と当source全6件の再発防止を確認する。Root/native/実サービスは実行していない。

| 対象 | 確認・非該当根拠 |
|---|---|
| WebRuntimeStop.begin/close | 唯一確認した同原因。元30秒を差分比較へ統一。独立STOP006が元MainでIOException/error1、修正後は25秒正常と期限+1ns拒否を確認。既001..005も正常順・UNKNOWN・phase/例外/0境界を再資格 |
| MaintenanceOwnerFrame.parentsGuard | deadline>=1の閉じたLinux絶対domain。native callerはLinuxMonotonicClockの非負秒/ナノ秒とmultiplyExact/addExact、後退も拒否する。同boot/親との正の絶対期限であり任意signed原点ではない。guard/認証実行無し |
| MorningParentBudget.borrow/deadlineNanos | borrowed absolute deadline>0、native同Linux domain。自身のelapsedはnow-began、期限生成はMath.addExactでoverflow拒否。signed System.nanoTimeの無検査加算と異なる。実Morning/budget生成無し |
| RootStartupPending.awaitLaunch | native callerがLinuxMonotonicClockを直接借用し、RootStartupContext.serviceRootDeadline/fixedDeadlineは正の親期限、systemd monotonic開始>0、multiplyExact/addExactを使う。WaitIoは内部観測portでnative絶対契約を変更しない。Root操作・当fixture実行無し |
| ExpiryAuditRepository | before/afterは削除前後のDB件数。非負/target/差分success条件でありclockでない。DB読取無し |
| CleanupExpiryExecution.verifyPriorAudit | 既auditのbefore/after件数とsuccess一致でありclockでない。原本読取・削除無し |
| AuthenticationService | afterはretry秒数int、LOCKED判定。nanoTime/deadline比較でない。業務実行無し |

追加の時間利用を確認：Web/ApiManagementServerのlock/joinとWebHttpAdmission.drainはdeadline-System.nanoTimeの差分、ServiceProcessResources.waitUnknownIntervalも同差分、QuestionSubmissionService.expiredはnow-start>=budget、InspectorUnitProbeはtimeout-(now-began)。いずれも同absolute比較ではない。MorningBackupReuse/Retentionはstartを引渡すだけで、BackupManifestReader/BackupArtifactVerifierのguardがclock-startの非負/所定期間を確認する。これらの業務・nativeの正当性や動的合格まで認定しない。

WebRuntimeStopのStep配列は既WebNativeRuntimeの固定非null literalで、各lambda内でnullable資源を個別確認する。constructorのclock null拒否を既001で確認する。今回、配列構築/close順/UNKNOWN保持/HTTPdrain中に必要なreplyの寿命を変更していない。

全対象は是正または上記非該当理由で区別し、追加回帰は既全Testクラスへ006を加えた形で行う。部分Test抽出やRoot fixtureの新設はない。正式1964/53・全451・実runtime・native・CHR・QA051 finalの受入は別未完。
