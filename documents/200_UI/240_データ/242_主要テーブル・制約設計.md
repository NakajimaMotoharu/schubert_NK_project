# 主要テーブル・制約設計

## 1. 目的・表記

主要tableのcolumn、PK、FK、UK、CHECK、indexおよび削除方式を基本設計粒度で定める。型の最終桁数、DDL名、tablespaceはSSで固定する。

関連RD: DAT-002～DAT-011、FUN-008～FUN-013、ASY-001～ASY-009、QST-007～QST-010。

表記: PK=primary key、FK=foreign key、UK=unique、NN=not null、CK=check。

## 2. `app_users`

| Column | 型 | 属性 | 意味 |
|---|---|---|---|
| id | bigint identity | PK | User内部ID |
| username | text | NN | 表示username、1～64 byte |
| username_key | text | NN,UK | NFC・trim・lowercase比較key |
| password_hash | text | NN | DelegatingPasswordEncoder形式 |
| role | varchar(5) | NN,CK | USER/ADMIN |
| status | varchar(8) | NN,CK | ACTIVE/DISABLED |
| failed_count | integer | NN,default 0 | User別失敗回数 |
| failure_window_started_at | timestamptz | NULL | 15分窓開始 |
| locked_until | timestamptz | NULL | User lock終了 |
| last_login_at | timestamptz | NULL | 最終成功 |
| password_changed_at | timestamptz | NN | 最終変更 |
| version | bigint | NN | Optimistic lock |
| created_at/updated_at | timestamptz | NN | 監査日時 |
| created_by/updated_by | bigint | FK(app_users),NULL可 | 初期bootstrapはNULL |

Index: `(role,status)`、`locked_until`。物理削除せずDISABLED。Active ADMIN 0人化はdeferred service checkとtransaction lockで拒否する。

## 3. `auth_sessions` / `login_ip_attempts`

### 3.1 `auth_sessions`

| Column | 型 | 属性 | 意味 |
|---|---|---|---|
| id | uuid | PK | Session内部ID |
| user_id | bigint | NN,FK RESTRICT | Owner |
| context_hash | char(64) | NN,UK | Raw contextのSHA-256 |
| context_ciphertext | bytea | NN | Response replay用AES-GCM暗号文 |
| issued_at/last_accessed_at/expires_at | timestamptz | NN | 8時間idle管理 |
| revoked | boolean | NN,default false | 失効flag |
| revoked_at/revoke_reason | timestamptz/text | NULL | 失効監査 |
| client_address | inet | NN | Login元 |
| created_message_id | uuid | NN,UK | Login Message ID |

Index: `(user_id, revoked, last_accessed_at desc)`、`expires_at`。同一user最大2件はtransaction内で古いsessionをrevokeして維持する。

### 3.2 `schubert_web_session.web_http_sessions`

| Column | 型 | 属性 | 意味 |
|---|---|---|---|
| id | uuid | PK | Web内部session ID |
| session_id_hash | char(64) | NN,UK | Cookieのrandom session IDのSHA-256 |
| attributes_ciphertext | bytea | NN | Allowlist属性（username、role、認証context ID、login日時、CSRF、safe SavedRequest）のAES-GCM暗号文 |
| key_version | varchar(16) | NN | 復号key version |
| created_at/last_accessed_at/expires_at | timestamptz | NN | HTTP session lifecycle |
| max_inactive_seconds | integer | NN,CK>0 | 8時間idle上限 |

業務tableへのFKを持たず、`schubert_web_session` roleだけがDMLする。属性はtype/version付きallowlistで復号後に検証し、任意Java
serializationを許可しない。Session fixation対策では新row作成と旧row失効を同一transactionで行う。Index `expires_at`。
期限切れrowは朝batchで削除し、DB backupから復元してもAPI `auth_sessions`が失効済みならLoginへ戻す。

`schubert_web_session.pending_context_revocations`は`id uuid PK`、`context_ciphertext bytea`、`key_version`、
`requested_at`、`attempt_count`、`next_attempt_at`、`expires_at`、`last_error_code`を持つ。Broker/API障害中のLogoutで作成し、Webの
recovery taskがIF-002成功後に削除する。`expires_at`以後はAPI sessionも無効であることを確認して削除し、raw/hashをlogへ出さない。

### 3.3 `login_ip_attempts`

`client_address inet`をPKとし、`failed_count`、`window_started_at`、`locked_until`、`updated_at`を保持する。期限切れrowは朝batchで削除する。

## 4. 現行master table

### 4.1 `games`

`id smallint PK`、`code text UK CK(NUKITASHI1/2)`、`title text NN`、`display_order smallint NN,UK`、`created_at`。
Code/title/display orderの2行は223の固定master値と一致させる。

### 4.2 `script_files`

`id bigint PK`、`game_id FK RESTRICT`、`display_order bigint NN`、`storage_relative_path text NN`、`display_path text NN`、
`file_name text NN`、`section_code text`、
`chapter_title text`、`sha256 char(64)`、`byte_size bigint CK>=0`、`created_at`。UK `(game_id,storage_relative_path)`、
`(game_id,display_order)`およびFK参照用`(id,game_id)`。`display_order`は現行file ID順から移行時に固定し、
NK内部ID再採番の影響を受けない。

### 4.3 `speakers`

`id bigint PK`、`game_id FK RESTRICT`、`name text NN`、`normalized_name text NN`、`is_protagonist boolean`、`notes text`、
`created_at`。UK `(game_id,normalized_name)`およびFK参照用`(id,game_id)`。

### 4.4 `script_entries`

`id bigint PK`、`game_id FK games RESTRICT`、`script_file_id`、`display_order bigint NN,UK`、`entry_index integer`、`line_number integer`、
`entry_type CK(dialogue/narration)`、`speaker_id NULL可`、`speaker_label`、`body text`、`body_search generated lower(body)`、
`raw_block`、`created_at`。UK `(script_file_id,entry_index)`およびFK参照用`(id,game_id)`。複合FK
`(script_file_id,game_id) -> script_files(id,game_id) ON DELETE CASCADE`、`(speaker_id,game_id) -> speakers(id,game_id) RESTRICT`
によりgame一致をDBで保証する。

Dialogueはspeaker必須、narrationはspeaker NULLの複合CKを維持する。BodyはUTF-8 4096 byte以内を移行時に検証する。
`display_order`は現行entry ID順から移行時に固定し、検索結果と同一entry index時の順序に使用する。`has_voice`は保持せず、
Index付き`entry_audio_links`の`link_type='voice'`存在から導出してlinkとの不一致を構造的に防ぐ。

### 4.5 `audio_files` / `entry_audio_links`

`audio_files`はgame、`storage_relative_path`、`display_path`、file名、basename、role、container、duration、size、hashとUK
`(game_id,storage_relative_path)`およびFK参照用`(id,game_id)`を持つ。`entry_audio_links`は`game_id`と1～999の`display_order`を持ち、PK
`(entry_id,audio_file_id,link_type)`、UK `(entry_id,link_type,display_order)`、複合FK
`(entry_id,game_id) -> script_entries(id,game_id) ON DELETE CASCADE`と
`(audio_file_id,game_id) -> audio_files(id,game_id) RESTRICT`、link_type CK(voice/se/bgm/other)とする。
これによりentry/audioのgame一致を保証する。1 entry・1 link typeの999件上限はdeferred constraint triggerでも保護する。

## 5. `media_assets`

| Column | 型 | 属性 | 意味 |
|---|---|---|---|
| id | bigint identity | PK | 内部ID |
| logical_id | varchar(64) | NN,UK | Web/APIで使うstable ID |
| media_type | varchar(8) | NN,CK | VIDEO/MUSIC |
| title | text | NN | 表示title |
| category | text | NN | MAIN/SUBTRACK/OVA/OPENING/BGM/曲等 |
| section | text | NULL | Music section |
| storage_relative_path | text | NN | Asset root基準。Descriptor用、Browser非表示 |
| display_path | text | NN | 現行表示を維持するsanitized論理path。File解決禁止 |
| file_name | text | NN | Safe download名 |
| byte_size | bigint | NN,CK>0 | Size |
| sha256 | char(64) | NN | Integrity |
| mime_type | text | NN,CK | 許可MIME |
| parent_logical_id | varchar(64) | FK(self),NULL | SUBTRACKのmain |
| pair_key/pair_role | text/char(1) | NULL,CK | Music pair |
| display_order | integer | NN | 一覧順 |

UK `(media_type,storage_relative_path)`。Index `(media_type,category,section,display_order)`。Video logical IDは223の固定値を使用する。
Music logical IDはNFC化したdisplay pathのUTF-8に固定prefix `SCHUBERT-NK:MUSIC:`を付けたSHA-256 lowercase hex 64文字とし、

| correlation_id | uuid | NN | 相関 |

`id bigint PK`、`message_id uuid UK`、`correlation_id uuid`、`destination`、`layout_id/version`、`body bytea`、

Index `(status,next_attempt_at,id)`。Bodyは内部work IDだけで質問本文を含めない。

## 9. `app_logs` / `batch_runs`

`app_logs`は現行ACTION/REQUEST/SECURITYにMQ/SYSTEM/BATCHを追加し、logged_at、level、action、message、request ID、
message/correlation ID、HTTP項目、remote address、details JSONBを保持する。質問/回答本文、password、tokenを保存しない。

`batch_runs`はrun ID、business date、step、start/end、status、target/success/failure count、byte数、error要約を保持し、
同一business date/stepの成功重複実行を防ぐUKを設ける。

## 10. 制約監査

SSでDDLを生成した後、全PK/FK/UK/CK、ON DELETE、NN、default、indexを機械抽出し本書と照合する。Migration testでは
orphan 0、entry/file/speaker/audioのgame不一致0、voice linkとの表示flag不一致が構造上発生しないこと、state不一致0、
削除flag不一致0、通知ありquestion物理削除不可、active ADMIN 1以上を検証する。

### 10.1 固定長数値との上限整合

- 固定長N12で送受信する`bigint` IDのsequence/identityは`MAXVALUE 999999999999`と同値CHECKを設定する。
- 固定長N9のoptimistic versionは0～999999999のCHECKを設定し、上限到達時は更新を拒否して`9001`を返す。
- 6桁page数に対応する対象queryの総件数上限は234の`PAGED48`に従う。
- DB上で有効な値がcodec変換例外になる状態を、DDL constraintと境界PTで防止する。
