# 主要テーブル・制約設計

## 1. 目的・表記

主要tableのcolumn、PK、FK、UK、CHECK、indexおよび削除方式を基本設計粒度で定める。型の最終桁数、DDL名、tablespaceはSSで固定する。

関連RD: DAT-002～DAT-011、FUN-008～FUN-013、ASY-001～ASY-009、QST-007～QST-010。

表記: PK=primary key、FK=foreign key、UK=unique、NN=not null、CK=check。

## 2. `app_users`

| Column | 型 | 属性 | 意味 |
|---|---|---|---|
| id | bigint identity | PK | User内部ID |
| username | text | NN | 表示username、1～64 byte |
| username_key | text | NN,UK | NFC・trim・lowercase比較key |
| password_hash | text | NN | DelegatingPasswordEncoder形式 |
| role | varchar(5) | NN,CK | USER/ADMIN |
| status | varchar(8) | NN,CK | ACTIVE/DISABLED |
| failed_count | integer | NN,default 0 | User別失敗回数 |
| failure_window_started_at | timestamptz | NULL | 15分窓開始 |
| locked_until | timestamptz | NULL | User lock終了 |
| last_login_at | timestamptz | NULL | 最終成功 |
| password_changed_at | timestamptz | NN | 最終変更 |
| version | bigint | NN | Optimistic lock |
| created_at/updated_at | timestamptz | NN | 監査日時 |
| created_by/updated_by | bigint | FK(app_users),NULL可 | 初期bootstrapはNULL |

Index: `(role,status)`、`locked_until`。物理削除せずDISABLED。Active ADMIN 0人化はdeferred service checkとtransaction lockで拒否する。

## 3. `auth_sessions` / `login_ip_attempts`

### 3.1 `auth_sessions`

| Column | 型 | 属性 | 意味 |
|---|---|---|---|
| id | uuid | PK | Session内部ID |
| user_id | bigint | NN,FK RESTRICT | Owner |
| context_hash | char(64) | NN,UK | Raw contextのSHA-256 |
| context_ciphertext | bytea | NN | Response replay用AES-GCM暗号文 |
| issued_at/last_accessed_at/expires_at | timestamptz | NN | 8時間idle管理 |
| revoked | boolean | NN,default false | 失効flag |
| revoked_at/revoke_reason | timestamptz/text | NULL | 失効監査 |
| client_address | inet | NN | Login元 |
| created_message_id | uuid | NN,UK | Login Message ID |

Index: `(user_id, revoked, last_accessed_at desc)`、`expires_at`。同一user最大2件はtransaction内で古いsessionをrevokeして維持する。

### 3.2 `login_ip_attempts`

`client_address inet`をPKとし、`failed_count`、`window_started_at`、`locked_until`、`updated_at`を保持する。期限切れrowは朝batchで削除する。

## 4. 現行master table

### 4.1 `games`

`id smallint PK`、`code text UK CK(NUKITASHI1/2)`、`title text NN`、`display_order smallint NN`、`created_at`。

### 4.2 `script_files`

`id bigint PK`、`game_id FK RESTRICT`、`relative_path text NN`、`file_name text NN`、`section_code text`、
`chapter_title text`、`sha256 char(64)`、`byte_size bigint CK>=0`、`created_at`。UK `(game_id,relative_path)`。

### 4.3 `speakers`

`id bigint PK`、`game_id FK RESTRICT`、`name text NN`、`normalized_name text NN`、`is_protagonist boolean`、`notes text`、
`created_at`。UK `(game_id,normalized_name)`。

### 4.4 `script_entries`

`id bigint PK`、`game_id FK RESTRICT`、`script_file_id FK CASCADE`、`entry_index integer`、`line_number integer`、
`entry_type CK(dialogue/narration)`、`speaker_id FK RESTRICT NULL可`、`speaker_label`、`body text`、`body_search generated lower(body)`、
`raw_block`、`has_voice boolean`、`created_at`。UK `(script_file_id,entry_index)`。

Dialogueはspeaker必須、narrationはspeaker NULLの複合CKを維持する。BodyはUTF-8 4096 byte以内を移行時に検証する。

### 4.5 `audio_files` / `entry_audio_links`

`audio_files`は現行column（game、relative path、file名、basename、role、container、duration、size、hash）とUK
`(game_id,relative_path)`を維持する。`entry_audio_links`はPK `(entry_id,audio_file_id,link_type)`、entry削除CASCADE、
audio削除RESTRICT、link_type CK(voice/se/bgm/other)とする。

## 6. `questions` / `answers`

### 6.1 `questions`

| Column | 型 | 属性 | 意味 |
|---|---|---|---|
| id | bigint identity | PK | Question ID |
| receipt_id | char(26) | NN,UK | Public random ID |
| owner_user_id | bigint | NN,FK RESTRICT | 所有者 |
| body | text | NN | 1～4096 byte |
| operation_token | uuid | NN | Browser冪等key |
| submitted_at | timestamptz | NN | 受付日時 |
| is_deleted | boolean | NN,default false | 論理削除 |
| deleted_at/deleted_by | timestamptz/bigint | NULL,FK | 削除監査 |
| version | bigint | NN | 競合制御 |

UK `(owner_user_id,operation_token)`。Indexはowner/日時、論理削除/日時、body GIN trgm。

### 6.2 `answers`

| Column | 型 | 属性 | 意味 |
|---|---|---|---|
| id | bigint identity | PK | Answer ID |
| question_id | bigint | NN,FK CASCADE,UK | 1質問1回答 |
| body | text | NN | 0～4096 byte。初期stubは空文字 |
| answered_at | timestamptz | NN | 回答日時 |
| provider_type | varchar(16) | NN,CK | STUB、将来EXTERNAL_AI |
| is_deleted | boolean | NN,default false | Questionと同時論理削除 |
| deleted_at/deleted_by | timestamptz/bigint | NULL,FK | 削除監査 |
| created_at/updated_at | timestamptz | NN | 日時 |

Question/answerの削除flag・日時は同一transactionで一致させる。

## 7. `async_jobs` / `notifications`

### 7.1 `async_jobs`

| Column | 型 | 属性 | 意味 |
|---|---|---|---|
| id | bigint identity | PK | Job ID |
| question_id | bigint | NN,FK CASCADE,UK | 対象質問 |
| owner_user_id | bigint | NN,FK RESTRICT | Owner |
| state | varchar(12) | NN,CK | RECEIVED/PROCESSING/COMPLETED/ERROR/CANCELLED |
| message_id/correlation_id | uuid | NN,UK/NN | MQ追跡 |
| received_at/state_changed_at | timestamptz | NN | 状態管理 |
| started_at/completed_at/error_at/cancelled_at | timestamptz | NULL | 遷移日時 |
| retry_count | integer | NN,default 0,CK 0..3 | 再試行 |
| last_error_code/message | text | NULL | 利用者向けと内部codeを分離 |
| version | bigint | NN | Compare-and-set |

Index `(state,received_at,id)`でFIFO取得、`(state,state_changed_at)`で運用照会。

### 7.2 `notifications`

| Column | 型 | 属性 | 意味 |
|---|---|---|---|
| id | bigint identity | PK | Notification ID |
| job_id | bigint | NN,FK RESTRICT,UK | 1 job 1通知 |
| question_id | bigint | NN,FK RESTRICT | 質問物理削除を保護 |
| owner_user_id | bigint | NN,FK RESTRICT | Login本人scope |
| notification_type | varchar(12) | NN,CK | ACCEPTED/COMPLETED/ERROR |
| state | varchar(12) | NN,CK | Job stateと一致 |
| accepted_at/state_changed_at | timestamptz | NN | 表示・cleanup基準 |
| error_code/error_message | text | NULL | ERROR時 |
| created_at/updated_at | timestamptz | NN | 監査 |

Index `(owner_user_id,state_changed_at desc,id desc)`、`(state,state_changed_at)`。Manual delete columnは持たない。

## 8. `request_inbox` / `mq_outbox`

### 8.1 `request_inbox`

| Column | 型 | 属性 | 意味 |
|---|---|---|---|
| message_id | uuid | PK | 業務Message ID |
| correlation_id | uuid | NN | 相関 |
| request_layout_id/version | char(8)/char(3) | NN | Request schema |
| owner_user_id | bigint | FK,NULL | Login前はNULL |
| operation_token | uuid | NULL | Browser冪等key |
| processing_state | varchar(12) | NN,CK | PROCESSING/COMPLETED/ERROR |
| result_ref_type/result_ref_id | text/bigint | NULL | 業務結果参照 |
| response_layout_id/version | char(8)/char(3) | NULL | Replay schema |
| response_body_encrypted | bytea | NULL | 必要時のみ暗号化response |
| created_at/completed_at/expires_at | timestamptz | NN/NULL/NN | Lifecycle |

UKは所有者scopeの`(owner_user_id,operation_token)`をNULLを考慮してpartial index化する。Passwordを含むrequest bodyは保存しない。

### 8.2 `mq_outbox`

`id bigint PK`、`message_id uuid UK`、`correlation_id uuid`、`destination`、`layout_id/version`、`body bytea`、
`status(PENDING/SENT/ERROR)`、`attempt_count`、`next_attempt_at`、`created_at/sent_at/last_error`を持つ。
Index `(status,next_attempt_at,id)`。Bodyは内部work IDだけで質問本文を含めない。

## 9. `app_logs` / `batch_runs`

`app_logs`は現行ACTION/REQUEST/SECURITYにMQ/SYSTEM/BATCHを追加し、logged_at、level、action、message、request ID、
message/correlation ID、HTTP項目、remote address、details JSONBを保持する。質問/回答本文、password、tokenを保存しない。

`batch_runs`はrun ID、business date、step、start/end、status、target/success/failure count、byte数、error要約を保持し、
同一business date/stepの成功重複実行を防ぐUKを設ける。

## 10. 制約監査

SSでDDLを生成した後、全PK/FK/UK/CK、ON DELETE、NN、default、indexを機械抽出し本書と照合する。Migration testでは
orphan 0、state不一致0、削除flag不一致0、通知ありquestion物理削除不可、active ADMIN 1以上を検証する。
