# ファイル・データ配置設計

## 1. 目的

Source、artifact、設定、秘密情報、business asset、transfer file、Artemis data、log、backupのlogical/physical配置と権限を定める。

関連RD: SYS-010、FIL-001～FIL-009、BAK-001～BAK-005、OPS-004～OPS-005、MIG-DAT-001～MIG-DAT-008。

## 2. 配置

| Logical root | 初期physical path | Owner/権限 | 内容 |
|---|---|---|---|
| Release root | `/opt/schubert-nk/releases/<version>` | root:schubert 0750 | Web/API jar、version manifest |
| Current link | `/opt/schubert-nk/current` | root所有symlink | Active release |
| Config root | `/etc/schubert-nk` | root:schubert 0750 | 非秘密設定、service env |
| Credential root | `/etc/schubert-nk/credentials` | root/service別 0700/0600 | DB/MQ/暗号key。Git禁止 |
| Asset root | `/srv/schubert-nk/data/assets` | data owner、Web/API read 0750 | Scenario/audio/video/music |
| Transfer root | `/srv/schubert-nk/data/transfer` | API write、Web read 0750 | `.part`/`.ready` |
| Backup root | `/srv/schubert-nk/backup` | backup service 0700 | Local日次backup 7世代 |
| Artemis root | `/var/lib/schubert-nk/artemis` | artemis 0700 | Journal、paging、large messages |
| Log root | `/var/log/schubert-nk` | service別、ops read 0750 | JSON application/batch log |
| Runtime root | `/run/schubert-nk` | tmpfs、service別 | PID/lock/socket。再起動で消去可 |

Pathは外部設定可能だが、asset/transfer/backup/log/Artemis rootを同じdirectoryまたは相互配下にしない。

## 3. Release構成

```text
/opt/schubert-nk/releases/1.0.0/
  web/schubert-nk-web.jar
  api/schubert-nk-api.jar
  lib/fixed-width-codec.jar
  db/migration/
  operations/
  VERSION
  SHA256SUMS
```

Release artifactはread-only。更新は新version directoryへ配置・hash検証後、停止中に`current` linkをatomic切替する。
SourceとMarkdownはGitを正とし、本番にはreleaseに必要なartifact・migration・operationだけを配置する。

## 4. Asset構成

```text
assets/
  scenario/
    NUKITASHI1/text/
    NUKITASHI1/audio/
    NUKITASHI2/text/
    NUKITASHI2/audio/
  video/
  music/
  manifests/master.sha256
  manifests/master-counts.txt
```

現行physical pathの維持は不要。DBにはasset root基準`storage_relative_path`と、現行画面用`display_path`を分離して保存する。
Scenarioはstorage `scenario/NUKITASHI1/text/...`に対しcurrent相当display path、音声はstorage
`scenario/NUKITASHI1/audio/...`に対しcurrent相当display path、Videoはstorage `video/main_part/...`に対しdisplay
`main_part/...`、Musicはstorage `music/曲/...`に対しdisplay `曲/...`とする。
Storage relative pathは`/`を論理separatorとし、
先頭`/`、`..`、`.` segment、NUL、backslash、空segmentを禁止する。
Display pathもNFC化し、絶対path、`..`、control文字を拒否してHTML escapeするが、OS path APIへ渡さない。

## 6. Transfer構成

```text
transfer/
  yyyyMMdd/
    <uuid>.part
    <uuid>.ready
```

File IDとnameはUUID。Permissionは0640、directory 0750を基本とする。APIは`CREATE_NEW`、Webはread-only。
Morning batchはrootそのものを削除せず配下fileだけを対象にする。Symbolic link、device、socketを検知した場合は削除せず警告する。

## 7. Backup構成

```text
backup/
  yyyyMMdd-HHmmss/
    schubert_nk.dump
    config.tar.enc
    MANIFEST.json
    SHA256SUMS
```

Manifestはhost、取得日時、app/schema/DB version、file size、hash、backup結果を持ち、秘密値を含めない。Config backupは秘密情報を
含むため暗号化する。同一SSD内である制約を明記し、将来NASへ`backup.root`設定変更で移行可能にする。

## 8. Log・rotation

- Web/APIはJSON Linesまたはjournaldへ構造化log、security/auditはDBにも保存する。
- File logは1 file 100MB、14世代、合計上限をserviceごとに設定する。圧縮世代を含めSSD 5GB以内を初期配分とする。
- Log file名に日付・serviceを含め、permission 0640。秘密情報を含むdebug dump、heap dumpを通常log rootへ自動生成しない。
- Prometheus/GrafanaのDEBUG監視dataは専用root、15日・5GB上限。STANDARDではserviceを停止する。

## 9. Git対象

| 対象 | Git |
|---|---|
| Source、Markdown、migration、script、設定雛形、manifest生成手順 | 対象 |
| Secret、runtime設定実値、DB dump、log、PID、transfer file、asset本体 | 対象外 |
| Asset manifest | 著作物pathの取扱いを確認した上で対象。Hash・件数は管理 |

`.gitignore`とsecret scanで禁止物を検出する。Source内に本番絶対pathを固定せず、defaultは外部設定・systemd unitで管理する。

## 10. Integrity・起動時検証

- API起動時: asset/transfer root実体、permission、同一でないこと、DB metadataとの代表file整合を確認する。
- Web起動時: asset/transfer root read permission、書込不可、descriptor verifier初期化を確認する。
- Migration時: 全対象fileのcount、byte、SHA-256、DB件数、orphanを検証する。
- 定常時: Disk、transfer件数/byte、asset欠落、Artemis journal、backup世代を監視する。
- Hash不一致を自動修復・上書きせず、配信停止・運用確認とする。
