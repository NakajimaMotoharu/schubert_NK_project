# メディア・ログ電文仕様

## 1. 目的・表記

IF-009～IF-017の要求・応答、内部IF-I02、media descriptor、一覧recordおよびLog検索・投影項目を定める。
位置は領域内の1開始相対byte位置。

関連RD: FUN-005～FUN-008、MQ-019～MQ-020、MQ-039～MQ-041、PER-004～PER-006、MON-002～MON-004、MON-007。

## 2. 共通media descriptor `MEDIA1024`（1,024 byte）

AUDRSP01、MEDRSP01の固定data全体とVIDRSP01の先頭1,024 byteに使用する。Browserへこのdescriptorを返さず、
Web内部だけで使用する。

| 項目 | 開始 | 長さ | 型 | 必須 | 許容値・意味 |
|---|---:|---:|---|---|---|
| Media logical ID | 1 | 64 | X | M | 要求IDのcanonical値 |
| Storage relative path | 65 | 512 | X | M | Business asset root基準。絶対path禁止、Browser非表示 |
| File name | 577 | 256 | X | M | 表示/download名 |
| File byte長 | 833 | 12 | N | M | 1以上 |
| SHA-256 | 845 | 64 | X | M | Lowercase hex |
| MIME type | 909 | 64 | X | M | 許可list内 |
| Content disposition | 973 | 1 | X | M | `I` inline、`A` attachment |
| Reserved | 974 | 51 | X | F | 全space |

Webはstorage relative path、size、SHA-256、MIME、dispositionを再検証し、不一致時は配信しない。配信ごとの全file SHA-256再計算は
大容量mediaの開始性能を損なうため行わず、移行manifestおよび定期integrity checkの値とmetadataを照合する。

|---|---:|---:|---|---|---|

| Display path | 1,297 | 512 | X | M | Sanitized表示専用。File解決には使用しない |

WebはCategoryから戻り先を`MAIN/SUBTRACK`=`/animation/main`、`OVA`=`/animation/ova`、`OPENING`=`/animation`へ決定する。

## 12. IF-I02 Web HTTP log event

### 12.1 `WLGEVT01` data（2,080 byte）

共通headerは区分`E`、同期非同期`I`、認証context全space。Response/TTLなし。WebはHTTP responseのstatusとelapsed確定後、
technical outboxから送信する。

| 項目 | 開始 | 長さ | 型 | 必須 | 許容値・意味 |
|---|---:|---:|---|---|---|
| 発生日時 | 1 | 17 | N | M | HTTP response確定時のJST |
| Log type | 18 | 16 | X | M | `REQUEST`または限定`ACTION`。組合せは下記QA-054規則 |
| Level | 34 | 8 | X | M | INFO/WARN/ERROR |
| Action | 42 | 64 | X | O | REQUESTは`HTTP_REQUEST_COMPLETED`（省略時API補完）、ACTIONは`MENU_VIEWED`必須 |
| Message | 106 | 512 | X | M | 本文・secretを含まない定型要約 |
| HTTP request ID | 618 | 36 | X | M | UUID |
| HTTP method | 654 | 8 | X | M | GET/POST等 |
| Path | 662 | 256 | X | M | Queryを除くURI path。制御文字なし |
| HTTP status | 918 | 3 | X | M | ASCII 3桁 |
| Elapsed ms | 921 | 9 | X | M | ASCII数字、0～999999999 |
| Remote address | 930 | 45 | X | M | 検証済みIPv4/IPv6 text |
| Username | 975 | 64 | X | O | 未認証はspace |
| Role | 1,039 | 5 | X | O | USER/ADMIN/space |
| Details | 1,044 | 1,024 | X | O | 表示用bounded JSON。本文、query値、cookie、tokenなし |
| Reserved | 2,068 | 13 | X | F | 全space |

API log ingestorはevent Message IDを`app_logs.source_message_id`へ一意保存し、重複時はDB更新せずACKする。Eventの
Correlation IDは対応する業務request Message ID、対応MQ requestがない場合はevent自身のMessage IDとする。入力値やexceptionを
無加工でMessage/Detailsへ複製せず、上限超過値はfield単位の定型要約/hashまたは省略で安全にbounded化する。Username/Roleは
監査表示用metadataであり、API認可判断には使用しない。

### 12.2 QA-054限定ACTION（UIC-011/SSC-336、2026-11-05承認）

利用者承認「この案で進めてよい」により、WLGEVT01は`REQUEST/HTTP_REQUEST_COMPLETED`と`ACTION/MENU_VIEWED`だけを受理する。ACTIONのAction省略・他action、未知Log type、category/actionの交差は恒久不正としDB接続前に拒否する。`LOG_SEARCHED`はAPI自身の業務成功監査であり、Web送信を受理しない。従来REQUESTのAction省略補完だけを維持する。

認証済みUSER/ADMINの正常メニューGETが成功終端した場合に`MENU_VIEWED`を一度生成し、既存local JSON→technical outbox→APIのsource_message_id UKへ保存する。REQUESTとは別event Message IDとし、HTTP request IDで同じ操作へ結合する。対応する業務MQがない場合、各eventのCorrelation IDはそれぞれ自身のMessage IDとする。失敗・拒否・HEAD・別画面を正常メニュー閲覧として記録しない。再配送で同eventのDB行を増やさない。

データ2,080 byte、header256 byte、全体2,336 byte、全fieldの開始・長さ・型、64 layout数は維持する。Log typeは固定REQUEST一値から上記二値の必須選択へ限定拡張する。ACTIONでも既存HTTP必須項目・安全な表示metadata・Details制約を維持し、権限を付与する電文にしない。API初回ログ検索の保存責務、検索snapshotと後発監査の区別はSS312/351に従う。
