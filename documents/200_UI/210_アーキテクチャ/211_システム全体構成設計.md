# システム全体構成設計

## 1. 目的

schubert NKのBrowser入口からDB・local fileまでの論理構成、単一server上の配置およびcomponent責務を定める。
現行の利用者向け挙動を維持しつつ、Web JavaとAPI JavaをArtemisで分離する。

関連RD: SYS-001～SYS-014、SCP-001～SCP-006、SCP-101～SCP-105、ENV-001～ENV-004、MQ-001～MQ-005。

## 2. 論理構成

```text
Browser
  │ HTTPS :55160
  ▼
Caddy（公開入口、TLS、security header、reverse proxy）
  │ HTTP loopback
  ▼
Web Java（Spring MVC / Thymeleaf / Spring Security）
  ├─ JDBC ─ PostgreSQL technical schema（HTTP session / Web log outbox、業務schema権限なし）
  │ JMS BytesMessage / fixed-width UTF-8
  ▼
Apache ActiveMQ Artemis（単一broker、永続File Journal）
  │ request/reply / internal async
  ▼
API Java（認証、認可、業務service、batch service）
  ├─ JDBC ─ PostgreSQL 18
  ├─ read ─ business asset root
  └─ write/read ─ large-result transfer root

Web Java ─ read-only ─ business asset root / transfer root
systemd ─ manages ─ PostgreSQL / morning batch / Artemis / API / Web / Caddy
```

Web Javaによるlocal file参照は、API Javaが返したdescriptorを検証した後のmedia配信と大容量結果取得に限る。
Web Javaはdirectory走査、任意path解決、業務DB参照および業務状態更新を行わない。

## 3. 物理配置

初期構成はUbuntu Server 26.04 LTS、Xeon Silver 4208、memory 16GB、local SSD 256GBの単一物理serverとする。
VM、container、Kubernetes、複数brokerおよび複数DB nodeは使用しない。単一server故障時の無停止継続は提供せず、
systemd再起動、日次backupおよび復旧手順で可用性を確保する。

| Zone | Component | 待受・接続 | 外部公開 |
|---|---|---|---|
| 公開入口 | Caddy | `:55160/tcp` HTTPS | 許可 |
| Application | Web Java | `127.0.0.1:46960` HTTP | 禁止 |
| Messaging | Artemis core/JMS acceptor | `127.0.0.1:61616` | 禁止 |
| Messaging管理 | Artemis console | `127.0.0.1:8161` | 禁止 |
| Application | API Java | HTTP待受なし。JMS Consumer | 禁止 |
| Data | PostgreSQL | `127.0.0.1:5432` | 禁止 |
| 運用 | Actuator health | Web/API別loopback port | 禁止 |

portは外部設定可能とし、表は初期defaultとする。変更時もCaddy以外をglobal interfaceへbindしてはならない。

## 4. Component責務

| Component | 主責務 | 禁止事項 |
|---|---|---|
| Browser | HTML操作、audio/video標準player、download、cookie保持 | MQ・DB・local fileへの直接接続 |
| Caddy | TLS終端、port 55160公開、proxy、security header、upstream障害応答 | 業務認証、業務data保持 |
| Web Java | HTTP入力検証、CSRF、server-side session、固定長変換、request/reply、HTML生成、検証済みfile配信、Web HTTP logのtechnical outbox登録 | PostgreSQL業務schema接続、role判定の最終決定、任意path参照 |
| Artemis | 永続message、FIFO、request/reply相関、再配送、DLQ、expiry | 業務dataの正本化、media本体格納 |
| API Java | 認証、session/role再検証、業務処理、冪等性、DB transaction、descriptor生成、非同期Consumer | Browserへ直接応答、公開port待受 |
| PostgreSQL | account、API認証session、Web技術session/log outbox、master metadata、log、通知、質問、回答、job、重複防止、outboxの正本 | media本体保存 |
| business asset root | scenario source、audio、video、musicの読取専用実体 | 可変業務data・一時結果の混在 |
| transfer root | 大容量結果の一時・確定file | 永続業務素材の配置、任意絶対pathの受渡し |
| systemd / morning batch | 依存順起動、非正常終了再起動、backup、削除、清掃、証跡 | 失敗を無視した業務data削除 |

## 5. Application構成

### 5.1 Web Java

- Spring Boot 4.1系、Java 25、embedded servlet container、Spring MVC、Thymeleaf、Spring Securityを使用する。
- HTTP Controller、View Model、MQ client adapter、fixed-width codec、media/file streaming adapterを分離する。
- HTTP用objectとMQ DTOを同一classにせずmapperを介する。
- HTTP sessionとWeb HTTP log outboxはPostgreSQLの専用technical schemaへ永続化する。専用roleには業務schema権限を与えない。
- Sessionの暗号化allowlist属性はusername、role、認証context ID、login日時、CSRF token、安全なSavedRequest、未完了更新の
  operation tokenだけとする。Password、入力本文および業務検索結果を保持しない。
- Web HTTP logはresponse確定後に本文・秘密値を除いた固定長`WLGEVT01`としてoutboxへ登録し、dispatcherがArtemis経由でAPIの
  `app_logs`へ投影する。Broker停止中もoutboxから再送し、同じeventを二重登録しない。

### 5.2 API Java

- 同じJava/Spring基盤を使用するが、Web Javaとは別process・別artifact・別OS accountとする。
- Request Consumer、protocol validation、dispatcher、application service、repository、file adapterを分離する。
- 同期Consumerは複数messageを処理可能とするが、同一messageの業務処理はtransactionalかつ冪等にする。
- 内部非同期Consumerは1とし、受付順に1件ずつ処理する。

### 5.3 共通library

固定長codec、header model、項目validation、NFC正規化、message ID規則、descriptor検証modelは共通library化する。
Web/APIで同じsource versionを使用するが、HTTP modelやDB entityを共通libraryへ含めない。

## 6. 設計上の互換性境界

| 現行挙動 | NK方針 |
|---|---|
| server-side HTMLと共通CSS | 維持 |
| Login、menu、search、scenario、audio、animation、music | 画面構成と操作性を維持 |
| 検索100件page、結果順、speaker候補順 | 維持 |
| audio inline/download、video/music Range | 維持 |
| URL/bookmark | 受入条件外。可能な範囲で現行pathを継続 |
| 全利用者がlog閲覧 | ADMINだけへ変更（RDのrole分離による意図的差異） |
| 平文account file | PostgreSQLのhash accountへ変更 |
| 単一JavaからDB直接参照 | Web/API分離、WebからはMQのみ |
| 手動Java起動 | systemd自動起動・再起動へ変更 |

## 7. 可用性と拡張境界

- Broker、DB、serverは単一構成である。HA追加時もWeb/APIの固定長interfaceを変更しない。
- 将来の外部AI server連携はAPI Java内の`AnswerProvider`境界で空回答stubと交換する。
- Caddyのsite addressと証明書を交換してもWeb/API artifactを変更しない。
- Backup先は設定でlocal directoryからNASへ変更可能にする。
