# 画面共通・レイアウト設計

## 1. 目的

全画面に共通するvisual language、入力、表示、操作、error、responsiveおよびaccessibility仕様を定める。

関連RD: SYS-006、FUN-002、PER-002～PER-004、TST-001～TST-005、MQ-028～MQ-033。

## 2. Page構造

```text
body
└─ main.page（最大幅1180px、左右中央、24px余白）
   ├─ header.topbar
   │  ├─ h1 + subtitle
   │  └─ nav + login user/role + logout
   ├─ flash message / validation summary
   ├─ filter or operation section
   ├─ pagination（一覧時）
   ├─ content cards/list/detail
   └─ pagination or action section
```

Loginは現行同様、最大幅420pxの中央cardとする。動画視聴だけ最大幅1280pxとする。

## 3. Visual仕様

| 要素 | 基本仕様 |
|---|---|
| Background | page `#f6f7f9`、card `#ffffff` |
| Text | primary `#202124`、secondary `#5f6368` |
| Primary/link | `#1f6feb`。hoverはunderline |
| Border | `#dde1e6`、radius 8px |
| Error | text `#8a1c1c`、background `#fdecec` |
| Success | text `#176b37`、background `#eaf7ee` |
| Focus | 2px以上のoutlineを消さず、keyboard focusを視認可能にする |
| Font | system UI font、本文16px相当、補足12～14px、h1 28px |

Desktopは2列menu、検索formは12 column grid、本文・media操作は現行幅を維持する。900px以下は1列化し、
横scrollを必要としない。Table形式の管理一覧はcardへ折り返すか、列見出しを維持した横scroll containerを使用する。

## 4. Navigation

- 全認証済み画面に`メニュー`linkと`ログアウト`buttonを置く。
- 階層画面は直近の上位階層linkを置く。Breadcrumbの代わりに現行のcompact nav linkを維持する。
- 更新はbutton、参照遷移はlinkとし、見た目だけで区別できること。
- 破壊的操作はred系secondary buttonと確認画面または確認checkを使用する。Browser JavaScriptだけのconfirmへ依存しない。

## 5. 入力共通規則

| 規則 | 仕様 |
|---|---|
| 文字code | UTF-8。電文化前にNFC正規化 |
| 前後空白 | 検索条件・usernameはtrim。Passwordと質問本文は自動trimせず、固定長paddingと区別不能な末尾ASCII spaceをerrorにする |
| 制御文字 | CR、LF、TAB、NULを拒否。質問本文も初期releaseは改行不可 |
| byte上限 | BrowserとWebで事前検証し、APIで再検証。超過値は切り捨てない |
| 必須 | labelに「必須」を表示し、HTML `required`とserver validationを併用 |
| 選択値 | 定義外値を400またはfield errorとし、DB条件へそのまま渡さない |
| 数値 | 全角数字を暗黙変換せずASCII数字だけ。範囲外はfield error |
| Date | 画面は`yyyy-MM-dd`、電文はJST `yyyyMMddHHmmssSSS` |

Searchの本文・章、Logのkeyword等は現行同様部分一致である。現行に最大長がなかった項目には、固定長電文とDB負荷を
保護するため上限を追加する。この差異は入力超過時に明示errorとなり、silent truncateしない。

## 6. 一覧・page共通

- 現行検索とlogは100件/page、新規通知・質問回答・User一覧は50件/pageとする。
- Page番号は1開始。0以下は1へ補正し、最終page超過は最終pageへ補正する現行挙動を維持する。
- 並び順は各画面で固定し、利用者入力の任意SQL sortは設けない。
- 上下に`前のN件`、表示範囲、総件数、`次のN件`を表示する。0件時は「該当するデータはありません」を表示する。
- 大容量検索はAPI側page単位で返し、Web Javaで全件保持しない。

## 7. Message・error

| 種別 | 表示例 | HTTP/処理 |
|---|---|---|
| Field error | `質問はUTF-8で4096 byte以内にしてください。` | 400相当。入力画面を再表示 |
| Authentication | `ユーザー名またはパスワードが正しくありません。` | 認証失敗を区別しない |
| Authorization | `この操作を実行する権限がありません。` | 403 |
| Not found | `対象が見つかりません。` | 404 |
| Conflict | `状態が更新されたため操作できません。再表示してください。` | 409 |
| Temporary failure | `現在処理できません。しばらくしてから再操作してください。` | 503 |
| Success | `更新しました。` | PRG後のflash message |

System error画面にexception、class名、Queue名、filesystem path、SQL、資格情報を表示しない。利用者向け追跡番号として
HTTP request IDだけを表示し、運用logと対応させる。

## 8. 操作中表示と二重送信

- GET検索buttonは連続操作可能だが、同一Browser responseの順序を画面側で取り違えない。
- 更新POSTはCSRF tokenと一回性operation tokenを使用し、button押下後はclient-sideでdisabled表示する。
- ServerはMessage ID/業務keyで冪等にし、JavaScript無効時の二重送信も防ぐ。
- 非同期質問送信は受付完了画面を表示するまで再送buttonを出さない。Timeout時の再操作は同一operation tokenを再利用する。

## 9. Accessibility・Browser

- HTMLの`lang=ja`、label/input対応、見出し階層、landmark、navの`aria-label`を設定する。
- Colorだけで状態を表現せず、状態textとicon相当の文字を併記する。
- Audio/videoはBrowser標準controls、videoは`playsinline`と`preload=metadata`、audioは`preload=none`を維持する。
- Mouseなしで全form、link、button、detailsを操作できること。
- 対応BrowserはST開始時点のChrome/Firefox/Edge現行安定版とし、JavaScriptなしでも主要業務を実行可能にする。

## 10. Security header・cache

- CSPは`default-src 'self'`を基本とし、style/img/media/formだけ現行相当を許可する。
- `frame-ancestors 'none'`、HSTS、nosniff、same-origin referrer、Permissions-PolicyをCaddy/Webで整合させる。
- 認証済みHTML、質問、通知、User、Log responseは`Cache-Control: no-store`。
- Mediaは認証を毎回検証し、private cacheまたはno-storeとする。Descriptorのstorage pathや物理pathをBrowserへ露出しない。
  現行表示を維持するsanitized `Display path`は別metadataとして表示だけに使用する。
