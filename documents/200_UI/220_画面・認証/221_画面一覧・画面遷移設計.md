# 画面一覧・画面遷移設計

## 1. 目的

schubert NKの全画面、URL、role、主要遷移および現行画面との差異を定める。

関連RD: SYS-006～SYS-007、SCP-001、SCP-006、FUN-001～FUN-013、AUT-001～AUT-003、TST-001～TST-005。

## 2. 共通方針

- Server-side HTML、UTF-8、共通CSS、responsive layoutを使用する。
- Login以外は認証済みsessionを必要とする。画面非表示だけでなくWebとAPIの両方でroleを検証する。
- 現行URLは受入条件ではないが、利用者の学習負荷を避けるため既存14画面のpathを継続する。
- 現行の画面名、2列menu card、top bar、検索form、card/list、media playerの視覚体系を維持する。
- 一覧の0件、前後pageなし、任意項目なしは操作不能なcontrolまたは明示文言で表現する。

## 4. 全体遷移

```text
SCR-001 Login
  -> SCR-002 Menu
       ├─ SCR-003 Scenario検索 -> SCR-007 本文 -> 音声再生/保存
       ├─ SCR-004 Game -> SCR-005 Route -> SCR-006 File -> SCR-007 本文
       ├─ SCR-008 Animation -> SCR-009 一覧 -> SCR-010 視聴
       ├─ SCR-011 Music -> SCR-012 分類 -> SCR-013 再生/保存
       ├─ SCR-018 質問要求 -> SCR-019 受付完了 -> SCR-020 通知一覧
       ├─ SCR-020 通知一覧 -> SCR-021 通知明細 -> SCR-023 質問回答明細
       ├─ SCR-022 質問回答一覧 -> SCR-023 質問回答明細
       └─ ADMIN
            ├─ SCR-014 Log検索
            └─ SCR-015 User一覧 -> SCR-016 追加 / SCR-017 詳細・変更
```

全認証済み画面のtop barからMenu、必要な上位一覧、通知一覧へ戻れること。BrowserのBack操作も通常GET画面で成立する。
更新POSTはPost/Redirect/Getとし、refreshによる二重更新を防ぐ。

## 5. Role別menu

| Menu | USER | ADMIN |
|---|:---:|:---:|
| Scenario閲覧・検索、Animation、Music | ○ | ○ |
| 質問する、通知、質問回答 | ○ | ○ |
| Log照会 | × | ○ |
| User管理 | × | ○ |

ADMINの質問・通知は通常利用機能として利用できる。通知はLogin本人分だけを表示し、ADMINであっても他人の通知は表示しない。
質問回答一覧・明細だけはRDに従い、ADMINが全利用者分を扱える。

## 6. 未認証・権限error遷移

| 条件 | 遷移・表示 |
|---|---|
| 未認証で保護GET | `/login`へ302。成功後は安全な保存済みGETへ戻す |
| 未認証で更新POST | Loginへ戻さず403。再login後に利用者が再操作する |
| USERがADMIN URLを要求 | 403共通error。対象存在の有無を開示しない |
| session期限切れ | GETはLoginへ、POST/AJAX/mediaは401/403相当を表示し再login案内 |
| 対象なし | 404共通error |
| MQ/DB一時障害 | 503共通errorまたは同一画面内error。入力値を秘密値以外再表示 |

## 7. 現行差異管理

意図的差異は次に限定する。Characterization Testで現行と比較し、その他の差異は不具合として扱う。

- Brand表示を`schubert NK`へ変更する。
- Log照会をADMIN限定にする。
- Menuへ質問・通知・質問回答、ADMINへUser管理を追加する。
- Login accountをPostgreSQL管理へ変更する。
- 共通error画面とsystem error再操作案内を追加する。
- URLは内部構成に応じ変更可能だが、本設計では既存pathを継続する。
