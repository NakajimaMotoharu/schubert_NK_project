## 2. 設計方針

- NKは現行projectと分離した`schubert_NK_project`独立Git repositoryで管理し、現行source/dataはread-only参照とする。
- 現行の画面構成、検索条件、表示順、100件page、media再生・保存およびRange操作を維持する。
- URLとbookmarkの一致は受入条件としないが、保守性に問題がない現行URLは継続利用する。
- Browser向けHTMLを生成するWeb Javaと業務処理を担うAPI Javaを分離し、両者の業務通信をArtemisへ集約する。
- Web Javaは業務DBへ接続しない。API JavaだけがPostgreSQLと業務素材metadataを操作する。
- 非text素材と大容量結果fileの本体はMQへ格納しない。API Javaが返すdescriptorをWeb Javaが検証して配信する。
- 固定長電文は共通header 256 byte、機能別固定data、0件以上の同一固定長recordで構成する。
- 軽微な具体値はRDの性能、設備、互換性およびsecurity条件内で決定し、その理由を各設計書へ記録する。

## 4. 読む順序

1. 211～213で全体構成と処理原則を理解する。
2. 221～226で利用者向け仕様と認証認可を確認する。
3. 231～237でWeb/API間の固定長interfaceとfile配信を確認する。
4. 241～243で永続dataとlocal fileの整合を確認する。
5. 251～254で運用・非機能・移行を確認する。
6. 261～265で後続工程への引継ぎ、要件充足、現行互換性、フェーズ完了判定を確認する。
