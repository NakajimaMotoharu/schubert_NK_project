# RD要件トレーサビリティ

## 1. 目的

RD正本の全281要件ID（QA番号と`SHA-256`表記を除く）から基本設計正本へのforward traceを示す。個々の設計書では設計項目ごとに
関連RDを併記し、本書では要件群単位の網羅性を管理する。`SYS-001～SYS-010`等の閉区間表記は区間内の各IDを個別に含み、
欠番を暗黙補完しない。

判定`充足`は「UI基本設計へ必要な設計を反映済み」を意味し、PG/IT/ST、実機確認、外部repository準備まで完了した意味ではない。
後続実施が要件の一部である行は状態を明記する。

## 10. 逆trace

各設計書冒頭の`関連RD`、個別tableの`Traceability`、本書のforward traceを組み合わせて逆引きする。SS以降はclass、DDL、
test caseに基本設計文書番号とRD IDを付与し、要件 -> UI -> SS/PG -> PT/IT/STのchainを維持する。
