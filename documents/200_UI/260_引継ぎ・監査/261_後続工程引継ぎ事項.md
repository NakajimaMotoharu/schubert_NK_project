# 後続工程引継ぎ事項

## 1. 目的

基本設計で確定した境界を維持しながら、詳細設計（SS）、実装（PG）、単体試験（PT）、結合試験（IT）、総合試験（ST）、releaseで具体化・検証する事項を管理する。

関連RD: SYS-011、SCP-004～SCP-005、TST-001～TST-005、TST-101～TST-103、SCM-001～SCM-006、T-001～T-005。

## 2. 基本設計で固定済みの事項

後続工程で無断変更しない。

- Caddy -> Web Java -> Artemis -> API Java -> PostgreSQL/local fileの責務境界。
- Web Javaの業務DB直接access禁止、Web/API間全業務通信のJMS `BytesMessage`固定長方式。
- 共通header 256 byte、64 layout、各項目位置・長さ・型・件数・電文長上限。
- Sync reply待ち2秒、persistent message、inbox/outbox、再配送最大3回、恒久protocol errorのDLQ隔離＋process終了。
- Internal async Consumer 1、FIFO、business timeoutなし、RECEIVEDだけ取消可能。
- 現行14画面の主要挙動、新規User/質問/通知/質問回答画面、USER/ADMIN scope。
- Question/answer論理削除、notification分離、backup成功後だけの物理削除。
- 取得ACKなしのlarge-result file、次回朝batch一括削除、media descriptor/Range方式。
- 毎朝のPostgreSQL -> backup -> 条件付きdata削除 -> transfer清掃 -> Artemis -> Expiry保守 -> API -> Web -> Caddy順。
- 単一server、同時10名、同期p95 2.5秒、RPO/RTO 24時間、STANDARD監視modeで本番運用。
- User管理・質問・取消・質問回答削除のoperation token＋payload HMAC冪等性、およびWLGEVT01によるWeb REQUEST logのoutbox/DB投影。

変更が必要な場合はRDFB/QAまたは後続工程の所定変更管理を使用し、関連interface、DB、運用、移行、試験を横断更新する。

## 4. PG（実装）

- Maven Wrapper/Java toolchainでJava 25とbuild toolを固定する。
- Web/API/common codecを別module/artifactとし、HTTP modelとDB entityをcommonへ混在させない。
- Source、migration、script、document、設定雛形をGit管理し、secret/asset/log/dumpを除外する。
- Main branchをrelease可能に保ち、短命branch、review、CI成功後にmergeする。
- Fixed layoutは手書きoffsetの重複を避け、定義とtestから総長・位置を検証する。ただし本設計のbyte値を変更しない。
- Password、context、question本文をdebug loggingしないことをcode review checklistへ含める。
- User更新・質問・取消・質問回答削除layoutでoperation tokenをAPIへ伝達し、owner/layout/target/payload HMAC一致時だけ保存済み結果を返す。
- Web HTTP filter、technical outbox、WLGEVT01、API log ingestorを実装し、本文・query値・secretを投影対象から除外する。
- 264の全`CHR-*`の実行可能Characterization Test harness、現行成功baseline（正規化JSON/HTTP header/screenshot）、source hashは2026-09-01にproductionと分離たGit commitへ固定し、CHR-G01～G06を全件PASSした。NK実装はこのgate commitより後だけで開始する。
- User-facing挙動を変更するrefactorは、該当Characterization Testを先に追加する。

## 5. PT（単体試験）

| 分類 | 必須試験 |
|---|---|
| Fixed codec | 全header field、全layout、padding、NFC、multi-byte境界、byte超過、禁止文字、長さ式 |
| Authentication | Hash、5/10回lock、15分窓、NK最大2 session・3件目の最古revoke（現行の3件継続はDIF-016）、role、owner |
| State | 全許可遷移、禁止遷移、取消/開始race、重複取消、logical delete |
| Idempotency | Message ID、operation token、outbox再送、response replay |
| SQL | 検索条件、sort、page丸め、FK/CK、index対象query |
| File | Normalize、root外、symlink、size/hash、partial、atomic rename、Range/416 |
| Batch | Backup success/failure分岐、cleanup条件、二重起動、途中再実行 |
| Redaction | Password/token/question本文がlog/metricへ出ない |
| Web log投影 | Broker/API停止中のoutbox滞留、復旧再送、event重複0、bounded field、local JSON保持 |
| Token再操作 | 同一payloadの0200、異なるpayloadの0105、Password HMACのoffline推測防止 |

## 6. IT（結合試験）

- Java 25、Spring Boot、Artemis、PostgreSQL 18の実機組合せで起動・通信・永続化する（T-001）。
- Web-Artemis-API-DB-fileの全IF正常系をlayout単位で1回以上通す。
- Broker/API/Web/DB停止、ACK前後crash、最大3回再配送、DLQ、Expiry、遅延responseを確認する。
- API停止中のQueue滞留、Broker reboot、outbox未送信、process reboot跨ぎを確認する。
- Scenario file mode 48MB上限、取得成功/失敗、翌朝削除、ACKなしを確認する。
- Notification/Question削除のDB backup成功/失敗分岐とFK RESTRICTを確認する。
- DEBUG監視modeでmetric、correlation trace、15日/容量設定を確認する。
- Web REQUEST logをWLGEVT01でDBへ投影し、Broker/API再起動跨ぎの欠落・重複0とLog画面検索を確認する。
- Internal work最終失敗でERROR通知とDLQが整合し、DB障害時のDLQ整合runbookで状態を放置しないことを確認する。
- Artemis File Journalの永続化・破損検知・Queue回復を確認する（T-004）。

## 7. ST（総合・受入試験）

- STANDARD監視mode、同時10名、各1同期要求でp95 2.5秒とmessage取り違え0。
- PG着手前に固定した同一Characterization Test artifactをNKへ再実行し、264の差異一覧以外が一致することを確認する。
- 初期AI外部通信が発生せず、空回答stub、処理済通知、質問回答検索が成立すること。
- 毎朝の計画停止、apt、reboot、依存順、backup 7世代、restore RTO 24時間を実証する。
- Process/OS障害とsystemd復旧を確認し、単一server無停止HAを期待値に含めない（T-002）。
- 16GB/256GBでmemory、disk、Queueの枯渇を発生させない（T-003）。
- 全量移行、hash、DB整合、public 55160/TLS警告、切替・切戻しをrehearsalする。

## 8. Release・SCM

- Release対象commitへ一意なversion tagを付与し、app/schema/config manifestを作成する。
- GitHub repository作成連絡後にremoteとCIを設定する。それまではlocal Gitを正とする（T-005）。
- CIはunit test、static analysis、format、dependency/security検査、package、Markdown link/trace checkを実行する。
- Release artifact、migration、systemd/config雛形、SHA256SUMS、operation documentを同じversionで固定する。
- Go判定前に未解決QA/RDFB、差異、test未実施、DLQ、backup/restore結果を確認する。

## 9. 将来AI連携への引継ぎ

初期releaseでは外部AI serverを実装しない。将来変更では`AnswerProvider`をSTUBからadapterへ交換し、QSBREQ/QSBRSP、
notification、question/answer schemaを破壊しない。外部応答待ち中はPROCESSINGのままConsumer 1を占有し、正常/異常通知後に
次へ進む。Timeout/skip/強制errorは新規要件・変更管理なしに追加しない。

## 10. 未確定ではなく実測で固定する値

次は要件QAではなく、設計上限内でSS/ITの実測により設定記録へ固定する。

- 導入時点のSpring Boot/Artemis/PostgreSQL minor/patch version。
- JVM heap/direct memory、PostgreSQL memory、Artemis journal/paging parameter。
- Query plan、DB index物理size、backup実size・所要時間、full manifest所要時間。
- Systemdの環境固有user/group、mount、public IP、証明書fingerprint。
- GitHub remote URL/CI credential（repository作成後）。
