# 障害表

## 1. 目的・採番規則

PG/PT中に、実装済み処理が承認済み仕様・独立oracleと異なることを確認した障害を、修正前に登録する。TDDで未実装機能へ最初に失敗する試験は障害としない。

- 採番: `BUG-001`から3桁連番。実際の最終番号を確認し、欠番・重複なく次番号を採る。
- 状態: `起票`、`調査中`、`修正中`、`再試験中`、`完了`、`見送り`。
- 共通原因、複数program/画面/電文/DB/設定/test、または予防確認が必要なら916にも起票する。
- 設計不備は本表だけで処理せず、RDF/UIC/SSC/QA分類を併用する。

## 3. 起票・完了規則

1. 独立oracleとの差を再現し、修正前の実際結果をsanitized evidenceへ保存する。
2. BUGを採番し、原因未確定欄は`調査中`として埋める。仕様影響があれば911～914を先に連携する。
3. 最小修正だけでなく影響範囲を検索し、916要否を判定する。
4. 修正commit、元Test ID、regression Test ID、再試験evidence/hashを記録する。
5. 全関連PT/CHRと必要な横展開がPASSした後だけ`完了`とする。
