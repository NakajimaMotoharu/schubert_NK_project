## 2026-10-18 generic資源factoryの例外型（BUG1422/YKT1186）

ResourceScope.acquire等のchecked Eを持つfactoryで、method reference/constructor/既owner返却がchecked例外を宣言しない場合、推論任せで公開throwsをIOExceptionへ広げず、既契約内のE（StorageIoException等）を型引数に明示する。追加する全factoryの取得型/実throw型/呼出側throwsを一覧照合し、取得後にObjects等を付加して型やnull契約を補完しない。null検査は取得直後の保護域内、実資源が無い場合はrelease0とする。独立compile/境界PTと静的gateを通し、同型先行修正だけで新展開先を未確認完了にしない。

## 1. 適用範囲と優先順位

Java 25、SQL/DDL、HTML/template、JavaScript、設定、shell、testへ適用する。優先順位はRD、UI、SS、本規約、個別実装判断の順とし、code都合で上位仕様やtest oracleを変更しない。Production artifactは`src`配下、Current/NK互換基盤は`program/characterization`配下へ分離する。

## 2. Java 25・命名

- Java releaseは25へ固定し、preview feature、internal JDK API、非決定的なdefault locale/timezone/charset依存を禁止する。
- Maven groupはSS 311どおり`dev.codex.schubert`、package rootは`dev.codex.schubert.nk`。packageは小文字、class/record/enumはUpperCamelCase、method/変数はlowerCamelCase、定数はUPPER_SNAKE_CASEとする。
- Interfaceへ機械的な`I` prefix、実装へ意味のない`Impl` suffixを付けず、責務を表す名称とする。
- Public class/method、電文field、DDL object、設定key、testにはProgram ID、RD要件ID、UI文書、SS文書、Test IDをJavadoc・注釈・隣接コメントまたは追跡表で辿れるようにする。
- Methodは一つの責務とし、boolean引数で無関係な挙動を切り替えない。公開APIの引数・戻り値・例外契約をJavadocへ記録する。

## 3. Module依存

- 正式artifactは`schubert-nk-protocol`、`schubert-nk-storage`（SSC-021）、`schubert-nk-bootstrap`（SSC084/088）、`schubert-nk-api`、`schubert-nk-web`、`schubert-nk-batch`の六個とし、SS311の許可方向以外の依存を禁止する。Storageは低位filesystem/native能力だけを持ち、Protocol/HTTP/DB/認証modelへ依存しない。利用は承認済みBootstrapの固定起動能力およびWeb/API/batchのfile adapterへ限定する。
- 共用Bootstrapは固定credential/proof/NSS・strict非秘密設定・固定role JDBC admission/sourceだけを所有し、内部module依存はStorageだけとする。API/Web/Root Batchからの参照はSS311 SSC084/088/126/142の限定範囲、HTTP/JMS/業務repository/任意role/DDL/一般process entryを追加しない。既存api/web.* package/binary名は互換名であってAPI/Web artifact依存を意味しない。Storageのnative-only/no-JDBCとWeb→業務API禁止を維持する。
- Protocolは固定長layout、value object、codec、error codeだけを持ち、Web/API/batch frameworkやDBへ依存しない。
- Web Javaは業務schemaへ直接accessせず、業務通信はJMS `BytesMessage`固定長電文だけを使用する。
- API Javaが業務transaction、owner/role再検証、Inbox/Outbox、DB/file整合を所有する。Batchはallowlistされた保守functionとbatch table以外へ任意accessしない。
- 循環依存、同一classのmodule間複製、productionからtest/Characterizationへの依存を禁止する。

## 4. Null・invariant

- Public/API境界、DB結果、設定値、collectionとその要素のnull契約を明示する。原則non-nullとし、欠落可能値は意味のあるvalue typeまたは戻り値の`Optional`で表す。
- Field、method引数、collection要素へNullability annotationを使用し、constructor/factoryで`Objects.requireNonNull`、範囲、format、相互条件を検査して不変条件を確立する。
- `null`を空文字、0、空collection、unknownへ暗黙変換しない。未知enum値、欠落設定、SQL NULL、form欠落は個別のnegative testを持つ。
- `NullPointerException`をcatchして正常系へ変換する実装、nullを返して制御する実装、raw collectionを禁止する。

  Framework adapterの限定例外（SSC071/PG194）: Spring MVCの直接HTTP終端では、HttpServletResponse引数と`@Nullable String`戻り値によるrequestHandled契約を使用できる。sendError/既存0102 handler完了直後だけnullを返し、成功template名はnon-null。業務helperへnullable成功値を伝播させない。根拠は固定Spring7.0.9のServletInvocableHandlerMethod.invokeAndHandleとServletResponseMethodArgumentResolverの契約（local jarのbytecode確認）、PT-SCR-005/006/007/014/016で終端/例外/二重render禁止を検証する。任意null fallbackやNPE正常扱いを許す例外ではない。

## 5. 例外・transaction

SS318の限定UNKNOWN keeperは診断/tick/fallbackのRTE/Errorで正常returnせず同failure frameを保持する。これは例外を正常処理へ握り潰す許可ではなく、再close/業務再送/Root再発行を行わない隔離である。fixed policy/observer/fallbackは取得前に準備し、tick故障はmonotonic1000ms fallbackで間隔を維持する。正常componentの例外規則やNPEを正常扱いしない規則を緩和しない。

- Protocol不正、validation、認証・認可、競合、再送可能な一時障害、永続障害を型またはerror codeで分ける。秘密値・電文本文・SQL parameterを例外messageへ含めない。
- Checked/uncheckedの選択は呼出側の回復責務で決め、広い`catch (Exception)`、空catch、例外握り潰し、正常制御への例外濫用を禁止する。
- Transaction境界はSS 312/324/332どおりservice methodへ置き、remote I/Oや長時間file transferをDB transaction内で行わない。
- DB更新とmessage送信はOutbox、受信重複はInbox/一意制約で整合させる。Retryは冪等性key、回数、delay、対象例外を固定し、無制限retryを禁止する。

  承認済QA050の限定例外：pending Logout失効再送だけは、真正0000/0200を確認するまで5秒/30秒/5分後に15分間隔で継続し、attempt_countは100で飽和する。新MessageID/元context・uniquelease/CAS・短TX/JMS待機時DB解放・最大100claim・Unit/owner期限と停止joinを必須とし、一般0102/未知期限/復号不能を自動削除proofにしない。これは他のmessage retry回数や無制限busy loopを許可する変更ではない。IT/STの性能問題による間隔調整・再試験はSS314/354を正とする。
- Lock順序、timeout、競合時error、rollback対象を明示し、並行testで検証する。

## 6. Logging・redaction・security

- 構造化logには時刻、level、component、event/error code、correlationの安全なprojectionを記録し、password、credential、secret key、raw session/cookie/token、CSRF、HMAC、固定長電文全文、質問/回答本文、DB dumpを出力しない。
- Redactionはdenylist置換だけに頼らず、許可fieldを明示する。例外stack traceにもsecret-bearing objectの`toString`を流さない。
- 認証・認可はdeny-by-default、USER/ADMINとowner scopeをWeb表示制御だけでなくAPI側で毎回検証する。DIF-016どおり同一account最大2 session、3件目で最古sessionをrevokeする。
- CSRFはstate-changing requestへ必須、cookie/sessionにはSecure/HttpOnly/SameSiteとno-store方針を適用する。Passwordはapproved encoder、operation token/HMACは定数時間比較とkey rotation契約を使用する。
- Credentialをsource、設定雛形、test、evidence、Git historyへ入れない。環境変数または0600外部fileへのreferenceだけを管理する。

## 7. SQL・DDL

- PostgreSQL 18互換SQLを使用し、Flyway migrationはappend-only、version一意、transaction可能性と切戻し方針を明記する。適用済みmigrationの書換えを禁止する。
- SQLはbind parameterを使用し、文字列連結、`SELECT *`、暗黙cast、無順序page、N+1、無制限resultを禁止する。
- PK/FK/UK/CK/NOT NULL/index/role/grantをSS 331へ一致させ、DB制約とJava validationの双方を独立testする。
- JDBC typed `getObject`はSQL projectionの物理型を確認する。PostgreSQL driverの`Long.class`はbigint専用であり、smallint/integerを読む場合は明示CASTまたは型対応読取り＋NULL検査を用いる。共通helperへの集約だけで型安全とはしない。実DDLの各型を使うPTを必須とする（BUG-030/086、YKT-027/077）。
- UTC InstantのDB bindはJDBC4.2 setObject＋OffsetDateTime UTC、projectionはgetObject(OffsetDateTime.class)＋null検査＋toInstantを使う。java.sql.Timestamp/getTimestamp/setTimestampは歴史暦差があるためProduction禁止（BUG167/YKT128/SSC056）。独立SQL literal/epochで0001～9999とµs・1582前後を検証し、同変換でfixtureとexpectedを作らない。表示時だけAsia/Tokyoへ明示変換する。列挙値と状態遷移はCHECK制約とapplicationの両方で検証する。
- `schubert_web`から業務schema、`schubert_batch`から任意table、`schubert_backup`から更新・復号keyへのaccessを禁止する。

## 8. 固定長codec

- SS 322/323の256-byte共通headerと64 layoutを一つのmetadata sourceで実装し、offset/length/charset/型/padding/必須/反復上限を明示する。
- 入力はNFC正規化後にUTF-8 byte長を検査する。文字数でbyte fieldを切らず、multi-byte途中切断、代替文字、暗黙trimを禁止する。
- 文字は指定方向へASCII space、数値は仕様どおり充填する。未設定と0を混同せず、全space規則をfieldごとに適用する。
- Encode/decodeはexact total length、header record count、反復領域一種類、未知code、reserved byte、overflow/underflowを検査し、恒久protocol errorは再送しない。
- Expected byte列はproduction codecから生成せず、SS offset/lengthから独立作成したgolden vectorを使用する。
- 独立fixtureもUI232のprofile表で検証する。error時はN=全0、B=space、X=space（個別overrideを除く）であり、正常B0とerror未設定を混同しない。B0/B1を入れたerrorを拒否するnegative canaryを持つ（BUG-043/085、YKT-038/076）。

## 9. 並行処理・JMS・file

- Shared mutable stateを避け、必要な状態はthread-safe typeまたはtransaction/lockで保護する。時刻、UUID、random、filesystem、JMS、DBは注入可能なportにする。
- 内部状態/secret/resource寿命の排他はprivate final lockで行い、callerが保持できるthis/class monitorを公開しない（BUG-036/YKT-032）。親classのintrinsic同期と整合必須の非公開・操作内所有adapterは、対象・理由と独立試験を記録する。
- Snapshot/recordへJDK objectを格納する際もimmutableを仮定しない。IPは検証済みnumeric literalのString等へ切離し、InetAddressの保存/直接公開をしない。入力/返却値の変化、redaction、SpotBugs EI_EXPOSE_REP/REP2を検証する（BUG-020/YKT-017）。
- Artemis address/queue、DLQ/Expiry、consumer並列数、persistent、redelivery `1秒/5秒/25秒`、PAGE/page-full FAIL/disk-full BLOCKをSS 321どおり固定する。
- Inbox/Outbox、operation token、HMAC、replayは重複・順序逆転・crash boundaryをtestする。
- Fileはcanonical root内だけ、symlink traversal拒否、temporary write+fsync+atomic rename、hash/size検証を行う。Rangeはsingle range、206/416、`Content-Range`、境界を明示する。

## 10. Testability・test規約

- SDKにpublic close()があってもAutoCloseable/Closeable実装とは推定しない。固定versionの実class宣言を確認し、必要なら既存と同じ明示owner adapter（interface実装と一回super.close転送）をfixtureへ適用する。close省略・warning抑止・SDK依存version変更で逃げず、全利用箇所と実bytecode/negative guardへ結合する（BUG1719/YKT1470、1826）。

- Provider latch/controlled callbackを止めた親threadは、同じprivate lockを取るgetter/renderを待つ前にlatchを解放し、元workerの有限終端を確認する。停止後access拒否のassertを削除せず、解放後に同期待を検査する。closeだけnonblockingという契約を全getterへ推定拡張しない。fixture順序の起動前guard/逆順反例を用い、待機上限延長やsleepで隠さない（BUG1718/YKT1469、1824）。
- throw-only lambdaとvar/diamondの組合せにはtarget generic型を明示する。wildcard値をObjects.requireNonNull→Optional.of等へ通してinvariant holderへ渡すときも、型引数又は受ける変数型を明示してcapture推論を確認する。RTE/Error factoryのchecked E規則とは別に、constructor/非取得callbackで検証する（BUG1716/1717、1818/1820）。

- UTC時刻のSQL境界fixtureには時差を明示し、時差なしliteralはsession TimeZoneで解釈される別入力として扱う。SET timezoneの関数内設定は呼出し前の引数型変換を変更しない。UTC/JST等の独立cast/Instant値をexpectedの根拠にする（BUG165/YKT127）。日付onlyの業務日oracleとUTC Instantを混同しない。

- 同worktreeのtargetを共有するMaven/reactor実行は直列にする。PGと独立PT作成は並行可能だが、-amの依存moduleも含めてtargetを共有するverify/test/formatを重ねない。重複探索のreportは正式証跡へ使用せず、終了後の単一clean verifyで再生成する（BUG164）。

- Generic callbackのBoolean結果は型付きboolean localへ受けてからJUnit assertTrue/Falseへ渡し、BooleanSupplierとのoverload推論競合を避ける。loop fixtureをlambdaへ渡す場合はiteration内の不変localへ確定し、更新されるloop変数をcaptureしない（BUG148/160/161、YKT125）。assertを省略したりwarning抑止で代替しない。
- TDDの最初の未実装failureは障害ではない。実装済み処理が承認済み仕様へ違反した場合は修正前にBUGを起票する。
- TestはArrange/Act/Assertを明確にし、一つのTest IDへ一つの目的を持たせる。純粋単体では時刻・ID・並行scheduleを制御し、sleep、外部network、実credential、実利用者dataに依存しない。SS354と利用者承認のある隔離component/native PTだけは、固定toolchainの実PostgreSQL/Artemis・Linux OS/native・loopback/専用LANのHTTPを使用できる。synthetic fixtureと認証済み専用環境/owner/期限/全資源後条件を必須とし、外部serviceや利用者本番dataへの一般的依存を許可しない。このPG/PT実証をIT/ST完了へ読み替えない。
- Form bindingはSS352 §8の明示field名allowlistを持ち、未知/大文字別名/空/null名をnegative testする。既知fieldの読取りだけをallowlist検査とみなさない。CSRF共通処理と業務form固有の検査責務を分離する（BUG-067/YKT-059）。
- 正常、境界、異常、例外、null、空、欠落、未知値、並行、重複、再送、rollbackを網羅する。Expectedはproduction methodを呼ばず、golden vector、DDL/SQL後条件、明示HTTP/DOM、固定暗号/hash vectorで独立算出する。
- `Failed`、`flaky`、`skipped`、`disabled`、`not-run`を合格へ算入しない。Line/method/class/branchは各100%を要求し、coverageだけを上げる無意味なassertionや安易な除外を禁止する。
- close後・二重close・close競合を試験する場合、対象resourceはplain try/finallyで必ず回収する。try-with-resources対象への明示closeによるjavac警告を抑止しない。新しいclose遷移fixtureにもこの既規約を適用し、owner宣言/finallyと元assert保持の起動前guard・旧TWR反例を結合する。通常の寿命はtry-with-resourcesを使用する（BUG-077/096/1722、YKT-087/1473、1834）。

## 11. Format・静的解析

- 表示snapshotがMap/List fieldを保持してgetterで返す場合、constructorでMap.copyOf/List.copyOfを明示する。Stream.toList/Map.ofEntriesの実immutabilityを解析器が認識しない場合も解析抑制を追加しない。返却変更拒否/入力変異非影響/並行snapshotを独立testし全SpotBugs0を確認する（BUG555/559、YKT399/403）。その場で新規生成するimmutable返却値とretained fieldを区別し、秘密・protocol recordをdisplay snapshotへ入れない。

- UTF-8、LF、末尾改行、space indentationを使用し、Java formatはSpotless/Google Java Formatのproject固定version、Markdown/YAML/XMLは再現可能なcheckを使う。
  Java整形はprojectの固定Spotless applyを優先し、CLIのlong-string再分割など異なる既定値でSQL oracleを変更しない。format終了codeを確認し失敗時は後続試験を開始しない（BUG-105/YKT-093）。
- Maven Enforcer、Compiler `-Xlint:all -Werror`相当、JSpecify＋NullAwayまたは同等、SpotBugs、PMD、Checkstyle/Spotless、JaCoCoをCIとlocalで同じ設定にする。
- SuppressionはID、理由、owner、期限、関連SS/Test IDを隣接記録し、package/file全体の抑止を禁止する。
- Shellは`set -eu`、ShellCheck 0 error、quote、固定PATH、秘密値非表示を守る。

## 12. 禁止事項

- RD/UI/SS、Current baseline、承認済みoracleを実装都合で変更すること。
- Force push、履歴破壊、branch protection回避、既存未commit変更の上書き・破棄。
- Production sourceを`program/characterization`へ置くこと、または`src`外へ混在させること。
- Hard-coded credential、raw token/session/cookie、master実体、DB dump、非redact evidenceのcommit。
- Reflection等によるprivate実装へのcoverage目的だけのtest、到達不能偽装、例外握り潰し、NPE正常扱い。
- 無承認の外部仕様変更、未起票障害の先行修正、未登録Characterization差分の許容。

## 13. Review checklist

規約適合、trace、null/例外/transaction、redaction/security、独立oracle、全分岐、並行/再送、秘密情報、関連PT仕様/evidence、BUG/YKT/SSCの同期をPRごとに確認する。

Traceでは485のcanonicalOwner/canonicalCostOwnerと変更群のchangeOwnerを分離する。既主担当を一律現作業群へ上書きせず、source hashと所有の根拠を保持する。新規pathの根拠不足はUNKNOWN、費用付替え/旧PTの新source資格化はしない。以後のincremental traceはtrace_owner_joinを使う（BUG1725/YKT1476、1840）。

### 証跡metadataの件数・集合契約（BUG1958/YKT1707、2026-10-28）

件数は固定値の複写でなく、対象を一意にするfinding ID集合・実XML・review行から導出する。fieldの意味、scope、分母、sourceを明示し、選択context件数と全sourceのraw件数を混同しない。未測定はnull。独立postも補助fieldと集合の一致、ID重複・欠落、別source、subsetの意味を検証する。同pathに複数指摘がある場合、pathだけのfirst-matchを禁止し、全attributes又は一意node IDまで照合する（BUG1959/YKT1708）。

凍結済みの誤metadataは原byte/hashと履歴結果を保持し、独立検証付き追補で有効値を結ぶ。補助件数訂正を製品PT、実測coverage、raw是正数、新受入へ変換しない。複数sourceの追補はdomain別に保持して合算しない。

同値fixture命名のCLI整形は確定TC artifactを使い、`--skip-reflowing-long-strings`を明示して元literal tokenを保持する（BUG1961/1962）。整形・plan・独立逆・normal Spotlessの各exitを分離し、末尾command0を先行成功へ流用しない。意味同一の未承認token分割をgeneric foldで隠さず、既存oracleを変更せず検証する。
