NK-WEB-001、AUT-001～004/MON-004、UI226/252、SS314/351 §2～4/352 §12、PT-WEB-095～100。WebSecurityAuditはJDK System.Logger、Clock、appVersion/configVersionをconstructor注入し、各callの新JSONをlocal loggerへ送る。許可eventはLogin成功/失敗/lock、CSRF/role/proxy拒否の6種類から開始する。各eventがSS351 catalogのaction/outcome/reason/levelを固定し、任意action/自由details/Throwable/request/bodyを入力にしない。CSRFはAUTHORIZATION_DENIED＋reason CSRF、API/JMS/REQUEST専用WLGEVT01へ投影しない。APIのcritical DB auditを代替しない。

HTTP request IDはserver生成UUIDを必須入力とし、Loginには検証済みnumeric client、成功には閉SessionPrincipalを必須とする。失敗Loginは利用者入力usernameを採用せずactorなしとし、lockだけ0..900の待ち秒数を持つ。拒否eventは安全に得られたactor/IPのみ任意で渡す。Principalからusername/roleだけをJSONへ取り出し、context/loginAt/オブジェクト自体を保存しない。usernameのNFCとCR/LF/TAB/U+2028/U+2029→spaceをSS351どおり行い、最大64byte内なので切捨ては不要。IPはliteralだけを正規化、scope/hostname拒否、DNSなし。versionは1..64 ASCII英数と._+-の閉じた設定値。timestampはClockをUTC millisecond固定表記。

eventごとに独立JSONを生成してSystem.Logger.log(level,json)だけを使用し、exception/causeをloggerへ渡さない。Loggerの出力先/journald・WARN固定などの最終runtime設定、request ID filterとHTTP handlerの接続は後続gate。logger故障を握り潰さず、local audit異常を正常化しない。API DB監査や実serverの監査到達を本unitで完了とはしない。追加dependencyなし。

PG-D-107補足（BUG-068/YKT-060、修正前）: 監査呼出には閉Route enumを必須とする。LOGIN=/login、LOGOUT=/logout、ALL_WEB=/**、ADMIN_USERS=/admin/users/**、LOGS=/logsを最初の既知filter/controller経路とし、実配線したmatcher/handlerに一致する値だけをcallerが選ぶ。ALL_WEBは全requestを対象とするproxy/CSRF filterの登録patternであり、任意URLの正規化fallbackではない。Login eventはLOGIN以外を拒否する。全eventにrouteを付与し、未知routeの追加は当該handlerのSS追跡/PTと同時に行う。利用者URL/query文字列をenumへ機械変換しない。
