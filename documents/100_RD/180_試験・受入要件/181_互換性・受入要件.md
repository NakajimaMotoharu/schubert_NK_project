# 互換性・受入要件

## 1. 基本方針

| ID | 要件 |
|---|---|
| TST-001 | 現行実装を正として、NK着手前に主要挙動のCharacterization Testを作成する。 |
| TST-002 | 画面デザイン、画面遷移、検索結果、並び順、ページング、メディア操作および主要エラーを比較する。 |
| TST-003 | 内部クラス構成、SQLおよびファイルパスの一致は受入条件としない。 |
| TST-004 | 現行から必要な変更は差異一覧へ記録し、理由と影響を確認した上で受け入れる。 |

## 2. 試験段階

| ID | 段階 | 主対象 |
|---|---|---|
| TST-101 | 単体試験（PT） | DTO変換、電文、業務処理、SQL、ファイル解決、冪等性 |
| TST-102 | 結合試験（IT） | Web-Artemis-API-PostgreSQL-ファイルの接続と障害系 |
| TST-103 | 総合試験（ST） | 現行互換性、性能、再起動、移行、運用、セキュリティ |

## 3. MQ固有試験

- 同一メッセージの重複配送
- Consumer処理中断と再配送
- 応答timeout後の遅延応答
- DLQへの移送と再処理
- Broker停止・再起動
- API停止中のQueue滞留
- 計画再起動を跨ぐ非同期要求
- correlation IDの誤対応防止
- 固定長電文の最小値、最大値、未設定値、multibyte境界
- 規定byte数超過、途中欠損、layout version不一致
- Header長、固定data長、record長、record件数および電文総長の不整合
- 文字・数値・booleanの充填文字、全充填の未設定値および変換例外
- MQ media descriptorからのlocal file解決とRange配信

## 4. 朝batch・backup試験

- 再起動後にPostgreSQL、朝batch、Artemis、API、Web、Web入口の順で起動すること
- Backup成功後の業務アプリ起動と7世代の世代管理
- 朝batchの二重起動防止および途中失敗後の再実行
- Backupから可変データをRTO 24時間以内に復元できること
