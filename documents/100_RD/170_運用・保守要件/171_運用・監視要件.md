# 運用・監視要件

## 1. 運用

| ID | 要件 |
|---|---|
| OPS-001 | PostgreSQL、Artemis、API Java、Web JavaおよびCaddy等の入口をsystemdで管理する。 |
| OPS-002 | 起動、停止、再起動、状態確認およびログ確認手順をスクリプト化する。 |
| OPS-003 | 毎日05:00頃のSSH経由運用処理に対応する。停止順、起動順、timeoutおよび失敗時動作を定義する。 |
| OPS-004 | OS、JDK、PostgreSQL、Artemisおよびアプリのversionを記録し、再現可能にする。 |
| OPS-005 | 秘密情報をGitへ登録しない。環境別設定と秘密情報を分離する。 |
| OPS-006 | Ubuntuのsecurity updateは`unattended-upgrades`を使用して日次適用できるようにする。 |
| OPS-007 | Security update適用後に必要な場合は05:00頃の計画再起動で反映する。 |
| OPS-008 | 一般updateはsecurity updateと分離し、適用周期と事前確認方法を別途定義する。 |
| OPS-009 | 再起動後は、PostgreSQL起動、朝batch、Artemis、API Java、Web Java、Web入口の順に依存関係を制御して起動する。 |
| OPS-010 | Backupその他の固定時刻業務処理を朝batchへ集約し、個別処理ごとの開始・終了・処理件数・成否を記録する。 |
| OPS-011 | 朝batchおよび業務アプリ起動処理は二重起動を防止し、途中失敗後に安全に再実行できること。 |

## 2. 監視・ログ

| ID | 要件 |
|---|---|
| MON-001 | Web、API、DBおよびMQのliveness/readinessを個別確認できること。 |
| MON-002 | HTTP request IDとMQ correlation IDを対応付け、WebからAPIまで追跡できること。 |
| MON-003 | 構造化アプリログ、認証・操作監査ログ、MQ処理ログを記録する。 |
| MON-004 | password、MQ/DB資格情報およびsession tokenをログへ出力しない。 |
| MON-005 | Queue滞留数、処理率、再配送数、DLQ件数、Consumer接続状態を確認できること。 |
| MON-006 | JVM、heap、GC、DB connection pool、ディスク残量およびHTTP応答時間を確認できること。 |
| MON-007 | ログおよびmetricに保存期間と容量上限を設定し、SSD枯渇を防ぐこと。 |

初期候補は、Spring Boot Actuator/Micrometer、Artemis管理機能、構造化ファイルログまたはjournaldである。
Prometheus/Grafanaは必要resourceを検証して採否を決める。OpenSearch/ELKは初期構成に対して過大なため候補外とする。

## 3. Git・CI

| ID | 要件 |
|---|---|
| SCM-001 | `schubert_NK_project`を独立Git repositoryとして管理する。 |
| SCM-002 | Markdown文書を含む開発成果物をGit管理する。 |
| SCM-003 | main branchをrelease可能な状態に保つ。branch、review、tag規則は別途決定する。 |
| SCM-004 | Maven Wrapper等によりbuild tool versionを固定する。 |
| SCM-005 | commitまたはmerge時に単体試験、静的検査、dependency検査およびpackage作成を自動実行できるCI構成を設ける。 |
| SCM-006 | GitHub repository作成後は、sourceと文書をGitHubへpushできる構成とする。 |

## 4. バックアップ運用

| ID | 要件 |
|---|---|
| BKO-001 | 可変DBデータおよび環境設定を自動バックアップする。 |
| BKO-002 | Backup先directoryを外部設定し、将来localからNASへ変更可能にする。 |
| BKO-003 | Backup成功・失敗、保存日時、対象DB versionおよびfile sizeを記録する。 |
| BKO-004 | 可変データbackupを毎朝の業務アプリ起動前に1回取得する。 |
| BKO-005 | Backupは日次7世代を保持し、RPO 24時間、RTO 24時間を目標とする。 |
| BKO-006 | 保持世代を超えたbackupは、新規backupの正常性を確認した後に世代管理処理で削除する。 |
| BKO-007 | Backup失敗時に業務アプリ起動を継続するか停止するかはQA-029で確定する。 |
