# 性能・可用性要件

## 1. 設備条件

| ID | 条件 |
|---|---|
| ENV-001 | CPUはIntel Xeon Silver 4208を基準とする。 |
| ENV-002 | 物理メモリは16GBを基準とする。 |
| ENV-003 | ローカルSSDは256GBを基準とする。 |
| ENV-004 | 単一物理サーバ、単一拠点を初期構成とする。 |

## 2. 性能

| ID | 要件 |
|---|---|
| PER-001 | 同時利用者数10名で機能を提供できること。通常想定は5名未満とする。 |
| PER-002 | 通常の同期画面操作は、Web打鍵から結果画面表示完了までの95 percentileを2.5秒以内とする。計画停止中、起動直後、障害試験中およびmedia本体の転送完了時間は除外する。 |
| PER-003 | MQ追加後も検索、閲覧およびログインの体感性能を現行から極端に悪化させないこと。 |
| PER-004 | 動画・音楽はRange要求により再生開始でき、ファイル全体の読込み完了を待たないこと。 |
| PER-005 | MQ Consumer数、prefetch、DB接続poolおよびJava thread数に上限を設け、16GB RAM内で過負荷を防ぐこと。 |
| PER-006 | Media操作は、Web Javaが再生開始に必要なRange応答を返すまでを応答性能の測定対象とする。 |
| PER-007 | ST工程以降は詳細監視を無効化した`STANDARD`監視modeで性能・受入試験および本番運用を行う。 |
| PER-008 | 監視modeの切替にアプリ再buildを要求せず、外部設定とservice起動設定で変更できること。 |

## 3. 可用性・再起動

| ID | 要件 |
|---|---|
| AVL-001 | 毎日05:00頃にアプリ停止、OS package更新、OS再起動、アプリ起動を行う計画停止を許容する。 |
| AVL-002 | OS起動後、PostgreSQL、Artemis、API Java、Web JavaおよびWeb入口を依存順に自動起動すること。 |
| AVL-003 | アプリプロセス異常終了時はsystemd等により自動再起動すること。 |
| AVL-004 | 同期処理中の計画停止では利用者に再操作可能なエラーを返し、処理結果不明を避けること。 |
| AVL-005 | 受付済み非同期処理は再起動後に継続または再実行できること。 |
| AVL-006 | 1台の物理サーバ故障時に無停止継続することは初期必須要件としない。 |
| AVL-007 | 毎朝の再起動後はPostgreSQLを起動し、可変データbackup、backup成功時の業務データ削除、受渡しfile清掃、Artemis、API Java、Web Java、Web入口の順に起動処理を進める。 |
| AVL-008 | 日次等の固定時刻に必要な業務処理は終了時batchへ配置せず、朝batchで順序制御する。 |
| AVL-009 | 固定長変換例外または恒久的protocol errorを検知したWeb/API Javaは非zero終了codeでprocessを終了し、systemdが自動再起動する。 |
| AVL-010 | 同一不正電文による無限再起動を防ぐため、一時障害は最大3回、恒久的protocol errorは再試行なしでDLQへ隔離する。 |

同一物理サーバ上の複数VMは、物理サーバ、電源、SSDおよびhost OS障害を共有するため、物理障害に対するHAとは扱わない。
