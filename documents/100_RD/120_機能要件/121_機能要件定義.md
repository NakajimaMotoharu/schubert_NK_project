# 機能要件定義

## 1. 現行移行機能

| ID | 機能 | 初期方針 |
|---|---|---|
| FUN-001 | ログイン・ログアウト | PostgreSQL保存の新規アカウント方式で再構築する。現行アカウントは移行しない。 |
| FUN-002 | メニュー | 現行機能への入口と画面構成を極力維持する。 |
| FUN-003 | シナリオ検索 | 本文、ゲーム、話者、章、種別、音声有無の検索挙動を維持する。 |
| FUN-004 | シナリオ閲覧 | ゲーム、ルート、ファイル、本文の階層閲覧を維持する。 |
| FUN-005 | 音声再生・保存 | OGG等の再生・保存を維持する。 |
| FUN-006 | アニメ視聴 | MP4一覧・視聴およびRange応答相当の操作性を維持する。 |
| FUN-007 | 音楽再生・保存 | 分類、一覧、再生および保存を維持する。 |
| FUN-008 | 運用・監査 | NKで必要な操作・障害・認証・MQ処理を記録し、確認できるようにする。現行ログの移行は行わない。 |
| FUN-009 | ユーザー管理 | ADMINがユーザー一覧、追加、無効化・有効化、role変更、password resetおよびlock状態確認・解除を実行できること。 |
| FUN-010 | 質問要求 | 利用者が質問を入力・送信し、受付完了を確認できること。 |
| FUN-011 | 通知情報 | 利用者が通知情報一覧・明細から受付、回答およびエラーを確認できること。 |
| FUN-012 | 質問回答検索 | 利用者が過去の質問・回答を一覧検索し、明細閲覧できること。 |
| FUN-013 | 質問回答削除 | 利用者が質問回答一覧または明細から対象の質問・回答を論理削除できること。削除後は即時に検索・閲覧対象外とし、物理削除はDB backup成功後の朝batchで行う。 |

## 2. 権限

| ID | Role | 権限 |
|---|---|---|
| AUT-001 | USER | 検索、シナリオ閲覧、音声、動画、音楽等の通常閲覧機能を利用できる。 |
| AUT-002 | ADMIN | USERの権限に加え、ログ閲覧およびFUN-009のユーザー管理を実行できる。 |
| AUT-003 | 共通 | 画面表示だけでなく、API Java側でも要求ごとに権限を検証する。 |
| AUT-004 | 認証session | Login成功時に固定長電文へ格納可能な不透明な認証context IDを発行し、利用者起点の各MQ要求でAPI Javaが有効性とroleを再検証する。 |

## 3. 非同期処理共通機能

| ID | 要件 |
|---|---|
| FUN-101 | 非同期要求に受付IDを採番し、利用者へ受付完了を返せること。 |
| FUN-102 | 非同期要求の内部状態を少なくとも受付、処理中、処理済み、エラー、取消済みで管理できること。 |
| FUN-103 | 再送された同一要求を重複処理しないこと。 |
| FUN-104 | 失敗時に再試行回数と最終失敗理由を確認できること。 |
| FUN-105 | アプリ再起動後も受付済み要求を継続または再開できること。 |
| FUN-106 | 非同期要求に個別の優先度を設けず、受付順に処理する。 |
| FUN-107 | 非同期要求に業務timeoutを設けず、取消またはエラーにならない限り処理対象として保持する。 |
| FUN-108 | 利用者は通知情報一覧で受付通知、処理済通知、エラー通知を検索し、通知情報明細で状態、回答またはエラー内容を確認できること。 |

## 4. 詳細化対象

URL、入力項目、表示項目、並び順、ページング、HTTPヘッダー、エラー表示および操作ログについては、
現行の挙動を自動試験で固定した後に本書へ詳細要件を追記する。
通知・非同期処理の詳細は`122_通知・非同期処理要件.md`に定義する。
