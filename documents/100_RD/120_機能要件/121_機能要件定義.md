# 機能要件定義

## 1. 現行移行機能

| ID | 機能 | 初期方針 |
|---|---|---|
| FUN-001 | ログイン・ログアウト | PostgreSQL保存の新規アカウント方式で再構築する。現行アカウントは移行しない。 |
| FUN-002 | メニュー | 現行機能への入口と画面構成を極力維持する。 |
| FUN-003 | シナリオ検索 | 本文、ゲーム、話者、章、種別、音声有無の検索挙動を維持する。 |
| FUN-004 | シナリオ閲覧 | ゲーム、ルート、ファイル、本文の階層閲覧を維持する。 |
| FUN-005 | 音声再生・保存 | OGG等の再生・保存を維持する。 |
| FUN-006 | アニメ視聴 | MP4一覧・視聴およびRange応答相当の操作性を維持する。 |
| FUN-007 | 音楽再生・保存 | 分類、一覧、再生および保存を維持する。 |
| FUN-008 | 運用・監査 | NKで必要な操作・障害・認証・MQ処理を記録し、確認できるようにする。現行ログの移行は行わない。 |
| FUN-009 | ユーザー管理 | ADMINがユーザーを追加できること。初期範囲に更新・無効化・password resetを含めるかは別途決定する。 |

## 2. 権限

| ID | Role | 権限 |
|---|---|---|
| AUT-001 | USER | 検索、シナリオ閲覧、音声、動画、音楽等の通常閲覧機能を利用できる。 |
| AUT-002 | ADMIN | USERの権限に加え、ログ閲覧およびユーザー追加を実行できる。 |
| AUT-003 | 共通 | 画面表示だけでなく、API Java側でも要求ごとに権限を検証する。 |

## 3. 非同期処理共通機能

| ID | 要件 |
|---|---|
| FUN-101 | 非同期要求に受付IDを採番し、利用者へ受付完了を返せること。 |
| FUN-102 | 非同期要求の状態を少なくとも受付、処理中、完了、失敗で管理できること。 |
| FUN-103 | 再送された同一要求を重複処理しないこと。 |
| FUN-104 | 失敗時に再試行回数と最終失敗理由を確認できること。 |
| FUN-105 | アプリ再起動後も受付済み要求を継続または再開できること。 |

## 4. 詳細化対象

URL、入力項目、表示項目、並び順、ページング、HTTPヘッダー、エラー表示および操作ログについては、
現行の挙動を自動試験で固定した後に本書へ詳細要件を追記する。
