# 移行・切替要件

## 1. 基本方針

| ID | 要件 |
|---|---|
| MIG-001 | 現行とNKは本番で並行稼働させず、停止を伴う一括切替とする。 |
| MIG-002 | 切替に伴う数時間のアクセス停止を許容する。 |
| MIG-003 | 移行対象はシナリオテキスト、音声、動画、音楽および検索・閲覧に必要なメタデータとする。 |
| MIG-004 | 現行ログおよび現行アカウントは移行しない。 |
| MIG-005 | NKのファイル配置は再設計可能とし、現行物理パスを維持しない。 |
| MIG-006 | 移行前に現行側の件数、容量、hash、DB件数および代表的検索結果を基準値として採取する。 |
| MIG-007 | 移行後に全素材の完全性、DB整合性、主要画面、検索、Range配信およびMQ疎通を確認する。 |
| MIG-008 | 受入不合格時はNKを停止し、現行を再起動できる切戻し手順を用意する。 |

## 2. 切替概要

```text
事前構築・試験
  -> 現行停止
  -> 最終素材・設定確認
  -> NK DB最終構築
  -> NK起動
  -> 受入試験
  -> 公開入口切替
  -> 合格判定
```

現行とNKを同時に本番公開しないが、切戻し判定が完了するまで現行プログラムと現行DBを削除しない。

## 3. 移行時に新規作成するもの

- NK用DB role、schemaおよび初期アカウント
- Artemis Broker instance、address、queue、role
- NK用systemd unit、設定、秘密情報
- NK用ログ・監視設定
- 素材manifestおよび検証結果
