# データ・移行対象要件

## 1. DB要件

| ID | 要件 |
|---|---|
| DAT-001 | DBMSはPostgreSQLとする。 |
| DAT-002 | DBスキーマはバージョン付きMigrationで管理する。初回DDLだけに依存しない。 |
| DAT-003 | アプリ実行用、DB Migration用、運用参照用の権限を分離する。 |
| DAT-004 | シナリオ、音声リンク、メディアメタデータおよびNKで新規作成する業務データの整合性をDB制約で保護する。 |
| DAT-005 | MQメッセージの重複処理防止に必要な処理済みIDを永続管理する。 |
| DAT-006 | 将来の非同期質問について質問、処理状態、回答、失敗情報を関連付けられる拡張性を持たせる。 |
| DAT-007 | 通知に受付ID、所有利用者、通知区分、内部処理状態、受付・処理・エラー・取消日時、correlation IDおよび回答等の業務データへの参照を保持できること。 |
| DAT-008 | エラー発生から24時間以上経過したエラー通知を朝batchで削除できるindexおよび日時情報を保持する。 |
| DAT-009 | 通知レコードと将来の質問・回答等の業務データを分離し、通知の削除が業務データを意図せず連鎖削除しない構造とする。最終的な保持範囲はQA-037で確定する。 |

## 2. 移行対象

| ID | データ | 方針 |
|---|---|---|
| MIG-DAT-001 | シナリオテキスト | 移行する。 |
| MIG-DAT-002 | 音声ファイル | 移行する。 |
| MIG-DAT-003 | 動画ファイル | 移行する。 |
| MIG-DAT-004 | 音楽ファイル | 移行する。 |
| MIG-DAT-005 | 検索・閲覧に必要なメタデータ | 現行素材から再生成または移行する。 |
| MIG-DAT-006 | 現行ログ | 移行しない。 |
| MIG-DAT-007 | 現行Webアカウント | 移行しない。 |
| MIG-DAT-008 | 現行ファイルパス | 維持しない。NKの配置設計に従い変更できる。 |

## 3. ファイル要件

| ID | 要件 |
|---|---|
| FIL-001 | 業務素材は本番サーバのローカルストレージへ保持する。 |
| FIL-002 | DBには物理絶対パスではなく、安定した論理IDまたは素材ルート基準の相対識別子を保存する。 |
| FIL-003 | 移行時にファイル数、総容量およびSHA-256等のハッシュで完全性を検証する。 |
| FIL-004 | アプリから参照する実体パスが許可された素材ルート配下にあることを検証する。 |
| FIL-005 | 大容量素材自体はGit管理対象外とし、マニフェストと生成・検証手順をGit管理する。 |
| FIL-006 | 大容量結果の一時受渡しfileは業務素材rootと分離した専用local directoryへ格納し、許可root基準の相対pathまたは論理IDで参照する。 |
| FIL-007 | 一時受渡しfileは作成途中の一時名と読取可能な確定名を分離し、byte長とSHA-256で完全性を検証する。 |
| FIL-008 | 一時受渡しfileはWeb Javaの取得成否にかかわらず日中保持し、次回朝batchで専用directoryから一括削除する。 |
| FIL-009 | 一時受渡しfileは一意な名前で作成して上書きを禁止し、件数と総容量を監視する。 |

## 4. バックアップ対象

| ID | 要件 |
|---|---|
| BAK-001 | マスタ素材はNKの定常バックアップ対象外とする。別途保存済みの正本から復元する。 |
| BAK-002 | アカウント、設定および将来追加する質問等の可変データをバックアップ対象とする。 |
| BAK-003 | 初期バックアップ先は本番サーバ内の分離したlocal directoryとする。 |
| BAK-004 | 将来NASを導入した際に、backup destinationの設定変更だけで移行できる構成とする。 |
| BAK-005 | 同一SSD内backupはSSD故障から保護できないことを運用上の制約として明記する。 |
| BAK-006 | 可変データbackupは毎朝の業務アプリ起動前に取得し、日次7世代を保持する。 |
| BAK-007 | BackupのRPOおよびRTOはともに24時間を目標とする。 |
